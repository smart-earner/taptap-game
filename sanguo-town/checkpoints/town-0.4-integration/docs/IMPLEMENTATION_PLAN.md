# 实施计划 v0.4｜城市优先，玩家操作轻

本计划替代旧“先补完整培养再扩城市”的顺序。当前代码仍为visual-0.2/core-0.1，本轮不含游戏实现。

| 阶段 | 实际要做的工作 | 退出标准 |
| --- | --- | --- |
| G1 | BuildingInstance、ConstructionProject、原子预留、劳力/项目位、暂停取消恢复、旧档映射 | 强制中断后只有未发生或完整发生，无重复消费 |
| G2 | 五阶段施工、建筑营业、道路入口、工人到离场、暂停表现 | 从空地到开业的真实画面，未建建筑不提前显示 |
| G3 | 持续DevelopmentPlan、保护线、周期经营与再投资、太守连续排程 | 一次方向确认推进三个合规项目，不逐笔请示 |
| G4 | 住区/仓储/商街/工造生活状态、CityMemory、聚合提案、城景默认入口 | 同视角看出差异；7日不处理仍发展 |
| G5 | 已批准0→30→60→90军团目标、征募训练整備、营地外观和军需限制 | 不瞬间满编，不无限扩军，供给不足自动降速 |
| G6 | 可选多城、物流与人事、跨城财政、30日离线、长期仿真 | 五种方针×三种查看频率×30/60/90日，记录真实差异 |
| G7 | 常驻收藏、形态精修、M4 GUI/多屏/能耗、签名公证 | 全部阻断缺陷关闭；无证据不标通过 |
| G8 | 可选按键/专注/行情，只读权限与故障回退 | 关闭联动仍可完整游玩 |

先完成G1—G4的一城切片再验证多城；不要把三城统计表当成主城成长。展示资产和功能必须并行制作：城建模型完成但没有新画面、只有画面却没有真实项目，均不算完成。

## 明确暂缓

完整人物培养树、复杂马匹繁育、全国地图、多个军团并发战争、语言模型自治社会、支付、账号系统。不是永久删除，是不得抢占真实城建与低频交互的优先级。

## 长期节奏不靠等三个月猜

开发快进只用于检查资源、事件、因果和视觉状态；不能用其结果宣称真实90天体验已好玩。先固定种子/决策/授权，在30/60/90日生成数据与同镜头城景，再做实际低频使用评估。

测试失败要具体区分：缺少内容、权限卡死、资源软锁、图像不随状态变化、过度提案、同城重复改建、军需挤占、纯等待。不能通过延长工时、自动发资源或增加通知掩盖问题。

现有Swift测试、macOS构建和本版CG验收分别记账，任何一个不能代替另外两个。
