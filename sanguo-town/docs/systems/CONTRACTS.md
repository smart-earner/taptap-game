# PRD v0.9 · 共享接口与状态归属

本文件是逻辑开发边界，不引入微服务、第二套模拟或新的强制类名。所有系统共享同一个原生引擎，不代表当前代码已拆成8个包。

## 全局不变量

单世界、单时钟、同一保存事务；金额和物料沿用原合同整数单位。S08负责原子发布，无独立创造资产的权力。动画不改经济；太守不能伪造玩家命令。

## 状态责任表

|状态|业务写入责任|消费边界|
|---|---|---|
|金币余额/来源/支出|S03真实金锭入库铸币；S01成功抽卡扣费；S08开局一次性初始化|S04只读缺口排生产；S06建设不扣币|
|RNG、保底、抽卡回执|S01经S08同事务提交|S07读取已保存结果，不重新掷骰|
|OwnedHero权益/到达预约|S01|S05预测供餐，S06预留床，S04到时建立同一居民实体|
|位置/任务/携货/休息|S04|S03/S05/S06提交需求，不瞬移人物；S07只投影|
|重复卡|S01重复抽创建；S02兑换创建、锁定或消费|所有写入经S08序列化；S04不能自动处理|
|星级/将魂|S02且仅玩家当次命令|S04只读能力，离线不得培养|
|资源lot、库存、WIP|S03采集加工；S04搬运；S05吃饭；S06施工|通过同一预留/转移/消费事务，不维护平行库存|
|床位/建筑/工程|S06；S04回报真实施工/迁居完成|重复卡不增加住房需求；容量只在COMPLETE增加|
|技能快照|S02定义；S03/S04/S06在合法阶段创建和结算|升星不追溯旧快照，UI不自行算收益|
|餐单/覆盖率/恢复模式|S05|S04保供优先，S03金炉受保护线约束|
|历史事件/成长册|所属业务产生真实eventID，S06管理留影|S05故事/S07回看只读，不重新结算|
|revision/保存/幂等索引|S08|全部系统经同一候选状态提交，失败不发布部分变化|

## 跨系统交接

以下是概念交接，不要求新建同名事件总线。持久字段和命令见[S08 §9.2—9.3](08_ENGINEERING_ACCEPTANCE.md#sec-9-2)。

|交接|必须携带或可追溯的信息|接收约束与失败处理|
|---|---|---|
|金锭卸入府署 → 金币|lotID、已兑换累计mU、实际卸货量、入库eventID|S03消耗整锭与增币同事务；S01只能花已提交余额；重放不重复发币|
|抽卡提交 → 权益或重复卡|commandID、poolVersion、结果、RNG/保底前后、扣费|S01/S02相关状态一起保存；S07保存后揭晓；失败整笔回滚，不泄露结果|
|新人权益 → 到任/床位/预测餐食|heroID、sourceDrawID、arrivalAt、床位预约|S05预测但不提前吃饭；S06无正式床用酒馆床；不能拒收已付费新人或复制本体|
|培养 → 星级/卡/魂|commandID、所选lot与数量、锁状态、星级前后、魂差额|S02原子消费；S04仅未来阶段用新能力；卡不足/锁定/保存失败不部分消费|
|生产/供餐/施工需求 → 任务|真实消费者、资源/量/地点、截止、优先级、预留|S04合并consumerKey，检查路线/班次/人力；等待给原因，已有货物安全交付|
|工程完成 → 容量/迁居|项目ID、物料与人工完成证据、目标床/住客|S06仅COMPLETE加容量；S04真实走路迁居；重复完成不再加床|
|全池满星 → 停新招募/金链|30个heroID的已提交星级|S01拒绝收费；S03/S04停新任务，在制/在途安全完成，保留币卡魂与城市生活|

## 唯一合同定位

- 同时刻顺序：[S04 §3.6](04_GOVERNOR_LOGISTICS.md#sec-3-6)。到达恰逢餐点不回填本餐名单。
- 命令权限、错误码、原子性：[S08 §9.3—9.4](08_ENGINEERING_ACCEPTANCE.md#sec-9-3)。同id同payload复用回执，同id不同payload拒绝。
- 技能快照和取整：[S02 §A.4—A.5](02_HERO_CULTIVATION.md#sec-a-4)。UI不得另定效果。
- 供给保护：[S05 §4.2](05_FOOD_LIFE.md#sec-4-2)；燃料保护：[S03 §2.6](03_PRODUCTION_ECONOMY.md#sec-2-6)。两者均须满足才新开可选消耗。
- 修改一个系统先测本系统，再测实际跨越的交接；改共享保存或事件顺序须做相关系统回归。完整GC断言只在S08维护。

## 原合同待裁决项

拆分保留这些既有差异，不静默改变玩法。开发涉及它们时，先明确口径，再同步正文/参数/测试。

|问题|原文|当前处理|
|---|---|---|
|晚巡120秒是否含往返|S04 §3.3写含去回程；S02 §A.4写真实120秒晚巡且合法返家|不宣称已一致；预览含往返，正式口径待明确|
|满意度“安抚”增益|S05 §4.4引用06A安抚，但S02六模板无该效果|不能自行接回旧技能，需明确移除引用或定义机制|
|特色工程完整报价/效果|S06 §7.1写沿用三路线，详细数值不在该小节|实现前三路线前核对历史与参数覆盖，缺项补齐后才算可直接开发|

这些不是拆分丢失的内容。其余预览与正式合同差距见[实现报告](../GOLD_TOWN_IMPLEMENTATION.md)。
