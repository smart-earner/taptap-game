# PRD v0.9 · 共享接口与状态归属

本文件是逻辑开发边界，不引入微服务、第二套模拟或新的强制类名。所有系统共享同一个原生引擎，不代表当前代码已按这些系统逐个拆包。

v0.11 战争增量另由[S09 天下战役](WAR_CAMPAIGN.md)负责；下述 v0.9/v0.10 接口在战争未启用的存档中仍保持原义。

## 全局不变量

单世界、单时钟、同一保存事务；金额和物料沿用原合同整数单位。S08负责原子发布，无独立创造资产的权力。动画不改经济；太守不能伪造玩家命令。

## 跨系统交接

以下是概念交接，不要求新建同名事件总线。持久字段和命令见[S08 §9.2—9.3](08_ENGINEERING_ACCEPTANCE.md#sec-9-2)。

|交接|必须携带或可追溯的信息|接收约束与失败处理|
|---|---|---|
|金锭卸入府署 → 金币|lotID、已兑换累计mU、实际卸货量、入库eventID|S03消耗整锭与增币同事务；S01只能花已提交余额；重放不重复发币|
|抽卡提交 → 权益或重复卡|commandID、poolVersion、结果、RNG/保底前后、扣费|S01/S02相关状态一起保存；S07保存后揭晓；失败整笔回滚，不泄露结果|
|新人权益 → 到任/候任/预测餐食|heroID、sourceDrawID、paidAt、arrivalAt、arrivalState、床位预约|v0.9按原规则进酒馆；v0.10承载不足进入候任，不吃粮不工作，按paidAt/heroID自动审核；两版都不能丢失已付权益或复制本体|
|培养 → 星级/卡/魂|commandID、所选lot与数量、锁状态、星级前后、魂差额|S02原子消费；S04仅未来阶段用新能力；卡不足/锁定/保存失败不部分消费|
|生产/供餐/施工需求 → 任务|真实消费者、资源/量/地点、截止、优先级、预留|S04合并consumerKey，检查路线/班次/人力；等待给原因，已有货物安全交付|
|工程完成 → 容量/迁居|项目ID、物料与人工完成证据、目标床/住客|S06仅COMPLETE加容量；S04真实走路迁居；重复完成不再加床|
|全池满星 → 停新招募/金链|v0.9为30人、v0.10为60人的已提交星级及poolVersion|S01拒绝收费；S03/S04停新任务，在制/在途安全完成，保留币卡魂与城市生活|

## v0.10 增量交接

- `MealWindowClosed`必须携带每个heroID的expected/served/quality，不再只给全城覆盖率；S05据此更新个人C/Q与happiness。
- `CycleClosed`携带每个heroID的连续休息、劳动、行走、装卸、换岗秒数；S05只据已提交证据算R/W，不读取动画位置猜测。
- `TaskStageStarted`读取当时个人happiness档位并保存modifierBP；S02/S04不得在阶段中途查询新值回算。
- `BreakthroughCompleted`由S06原子更新武将hardCap、已解锁网格和院落许可ID；S04另按真实需求建地块设施，S01不能把许可当作空户位。
- `ResidentAdmissionCommitted`必须同时写常住数、单人Household、合法住处预约（正式户位加人位或酒馆客床）和下一餐预测；提交失败仍是WAITING_RESIDENCY。
- `ResidenceTransferCommitted`须同事务释放旧客床/旧租约/旧户位并锁定新院落户位和人位；任何保存失败保留原居住归属，不能一人两户或无家可归。
- `HealthConditionStarted`必须携带触发cycle、duty/rest/happiness和危险阶段证据；S05校验后写入，每人及每城限额内才接受。
- `ClinicTreatmentCompleted`必须携带患者、医生、诊床、阶段劳动/休养证据；S05清状态、S06放床、S04结束任务同事务，失败全部保留。

## v0.11 战争增量交接（NOT_IMPLEMENTED）

- `CampaignStarted`仅在新档 `createCity` 后首次世界推进或旧档 format6 迁移后首次正常推进写入一次，携带 UTC 时间水位、12 城/44 点与有限敌仓；不得把旧档历史天数折算成已征服进度或免费士兵。
- `RecruitSquadCommitted`须同时扣地区兵源、足额木/石/铁/工具实材及训练劳动，并建立唯一装备编队；保存失败不得留下半个编队或复发兵。
- `TroopUpkeepCommitted`按从战役启动起的 86400 秒日界、存活士兵数、仓点、军粮批次与民用保护线一次扣费；重复日水位不可再次扣粮，断供按短缺军粮每份最多散失 2 名士兵，不得侵占民用两餐。
- `ExpeditionAuthorized`须有目标城市下一合法边防点或主城、邻接/可达、1—4 名唯一健康武将、足额有装备士兵且未超统率容量、首都 2 名可工作者、前线实物军粮与未来 24 小时兵员日耗，以及 S05 两餐/4Nforecast 保护证据；S09 不可从抽卡钱包扣费或复制劳力。
- `HeroAssignmentChanged`在首都、远征、驻防、外城矿务之间原子转移，住房归属保留；S04、S05 与 S07 按同一值排班、计算餐食及显示，不能一人两地。
- `BattleCommitted`须携带 battleID/pointID、战前真实参战编队与武将快照、精确攻守公式、器械/战法消耗、胜负、按最大余数法分摊的永久战损、点位 owner/情报与现场战利品/首胜 receipt；S08 持久化后才发布地图演出，同一 battleID 重放不得双扣、双占或双领奖，现场仓满只记限量待运战利品。
- `CityCaptured`只能在本城 outer/supply/gate 当前均 HELD、core 决战获胜后原子提交城市归属、独有许可和地区兵源资格；边防点首胜不触发城市解锁。
- `RaidResolved`先以真实驻防编队/武将结算永久战损，再仅在可掠余量内转移库存或为一栋非核心建筑记损坏；S05 民粮保护、S06 修复、S08 失败回滚共同生效。边防点/边境城失守与补给断路须同步暂停当地生产和新远征；复占不能重发首胜战利品。
- `CampaignCompleted`仅在 S09 全部城市归属、各城三处边防点仍为我方 HELD、敌方核心败北及补给可达同一事务成立时写一次；v0.10 全员满星只关闭招募与新开金链，不触发此事件。

## 唯一合同定位

- 同时刻顺序：[S04 §3.6](04_GOVERNOR_LOGISTICS.md#sec-3-6)。到达恰逢餐点不回填本餐名单。
- 命令权限、错误码、原子性：[S08 §9.3—9.4](08_ENGINEERING_ACCEPTANCE.md#sec-9-3)。同id同payload复用回执，同id不同payload拒绝。
- 技能快照和取整：[S02 §A.4—A.5](02_HERO_CULTIVATION.md#sec-a-4)。UI不得另定效果。
- 供给保护：[S05 §4.2](05_FOOD_LIFE.md#sec-4-2)；燃料保护：[S03 §2.6](03_PRODUCTION_ECONOMY.md#sec-2-6)。两者均须满足才新开可选消耗。
- 修改一个系统先测本系统，再测实际跨越的交接；改共享保存或事件顺序须做相关系统回归。完整GC断言只在S08维护。
