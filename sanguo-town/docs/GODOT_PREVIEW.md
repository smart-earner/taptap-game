# Godot 桌面大地图

Godot 负责 3D 场景、角色动作、镜头和界面；现有 Swift `SanguoLife` 继续负责唯一的经济、任务和存档。正式新档使用 `hero-town-0.9.0`，旧 `hero-town-0.9-preview1` 只保留兼容读取。

## 不可退化的桌面模式

用户明确要求保留平铺桌面。**Godot 已接通 macOS 原生透明桌面层，并在本机内建屏验证；原生旧版仍保留。** 这是覆盖选定屏幕的真正二维画布，不是把3D沙盘的摄像机竖起来，也不是最大化窗口或独占全屏。layout6按1920×1080世界展开18个稳定地块、4×5主路网、24个田位和独立住宅节点；地形和正立建筑铺满屏幕，未建设地块只显示弱化的规划记号，不伪造已建建筑。可交互管理窗口仍可使用3D斜视镜头；二维桌面层和管理窗口读取同一份已提交世界状态，共用唯一模拟时钟。

正式迁移的发布门槛：透明桌面图层、鼠标穿透、低于工作窗口、不改变壁纸/桌面文件、不创建独占全屏 Space、多屏及退出恢复；独立可交互管理窗口与桌面城景共享一个模拟时钟和同一个世界。当前已验证基本窗口属性、透明像素、单时钟、隐藏恢复、清理及菜单往返；外接屏真实热插拔、不同 Spaces/全屏应用组合、长时能耗仍待实机验收，不能声称完整兼容性验收通过。

已有 `SanguoTown-GoldTown.app` 及原桌面代码、原存档保持不变；本次没有删除其桌面入口。

## 本机运行

需要 macOS、Swift 命令行工具和官方 Godot 4.7.2。当前机器的 Godot 放在仓库外层 `.tools/godot/Godot.app`，没有覆盖系统应用。也可设置 `GODOT_BIN` 指向本机 Godot 可执行文件。

```sh
bash scripts/run-godot.sh
```

也可以在 Finder 双击项目内的 `打开Godot小城.command`。

脚本编译 Swift 桥接程序及 AppKit GDExtension，并复制资源 bundle 到被 Git 忽略的 `godot/bin/`，导入后启动 Godot。只使用本机 Clang/Swift，不要求安装整个 Xcode 或重新编译 Godot。打开 Godot 编辑器前也先运行一次此脚本准备组件。

操作：右键拖动旋转、滚轮缩放、点击武将打开名册；底栏提供酒馆、培养、建筑形态、物资说明、桌面模式及 0/1/6/30 倍速。开局默认为 6 倍演示速度，不计算退出后的离线收益。

### 桌面使用方式

1. 底栏「桌面模式」→「开启桌面平铺」，可选择显示器；二维城景自动铺满该屏幕。
2. 「收起管理窗口，回到桌面」；开启桌面后点管理窗口的关闭按钮，也只是收起。
3. 从系统菜单栏状态项「小城」，或本应用菜单「小城」，打开城务、酒馆或培养。
4. 「显示 / 隐藏桌面小城」只控制图层；「暂停 / 继续经营」控制唯一模拟时钟。
5. 菜单「退出小城志」或 Command-Q 才彻底退出：完成正在进行的保存，撤去桌面层与菜单栏项。

偏好保存于 Godot 的 `user://desktop.cfg`，不进入经济存档。外接显示器暂时缺失时回退到主屏，保留原显示器 ID 等待恢复。夹具测试不写玩家偏好。

### 单世界架构

`main.gd` 是唯一经营请求发起者。第二个原生 `Window` 用二维 `Control` 只读投影同一份已提交快照，没有再实例化一套角色、生产逻辑或时钟。`desktop.gd` 只负责二维画布和窗口操作；AppKit C ABI 扩展只修改本进程拥有的 NSWindow。

桌面层透明、不可成为键盘窗口、鼠标穿透，层级为壁纸之上/桌面图标之下。不会请求辅助功能、录屏、输入监听权限，也不更改壁纸或桌面文件。管理窗口收起后降至 15 FPS，停止管理视口渲染，经营继续。完整能耗尚未测量。

原生组件持有整个运行周期的 `frontend.lock`，同一存档的第二个客户端不能再推进时间；临时 `bridge.lock` 仍保护每次存档事务。退出前先等待正在执行的桥接保存，再释放前端锁。

## 可玩范围

- 微缩低多边形 3D 地形、石路、林地、河岸、中式屋顶和建筑。
- 五名初始武将的不同外观，行走、工作、搬运状态读取真实任务；头顶不展示姓名。
- 采金、冶炼和金锭交付产生金币；没有画面层的赠币计时器。
- 真实单抽/十连，先保存后揭晓；30 人池、概率、保底及重复卡全部使用现有引擎。
- 手动升星、将魂兑换、首批重复卡的锁定/分解；消耗型培养操作先确认。完整批量重复卡管理尚未迁移。
- 民居一至三阶模型对比；对比按钮不修改世界、不消耗资源。城中真实建设状态由太守和现有引擎驱动。
- 物资放在独立小笺中，不让常驻资源面板遮住场景。
- 矿筐、待运金锭、工作工具与冶炼烟气由真实库存/任务/工序驱动；金币飘字只来自已保存的累计铸币差额，重开不重播历史收益。
- 酒馆可打开「金币的来路」：实时展示开采、运输、炉边成品、实际交付与可招募次数，并可聚焦相应建筑。
- 抽卡结果说明新武将专长；培养页提供一/三/五星技能及当前任务倍率。数值从同一参数包和任务读取，不在渲染层新增经济加成。

## 存档和事务边界

新存档固定为 `~/Library/Application Support/SanguoTown-GodotPreview/world.json`，**不读取、不迁移、不覆盖**原 GoldTown 存档。

`GodotBridge.swift` 使用文件锁串行读取、执行、校验和保存。玩家命令携带唯一 commandID，复用原引擎的幂等收据；保存成功后才返回抽卡结果。失败返回错误而不是候选世界。Godot 同时只发一个请求；推进请求不会自动重试。默认从真实推进到第 300 秒的新城开始，不伪造物资。

测试可以用 `SANGUO_GODOT_SAVE=/tmp/godot-fixture-...` 指定专用临时目录；桥接拒绝其他名称的存档目录。该名称检查用于防止误操作，不是安全沙箱。

```sh
swift build -c release --product SanguoLifeCLI

bash scripts/run-godot.sh --headless --editor --import --quit

SANGUO_GODOT_SAVE=/tmp/godot-fixture-input bash scripts/run-godot.sh --headless --script res://scripts/ui_input_smoke.gd
# 以下需要真实 macOS 图形会话，会短暂创建测试桌面窗口并自动清理：

```

桥接测试自动创建并清理自己的临时目录，验证扣费、幂等、失败无副作用、真实铸币和存档隔离。场景测试检查实际桥接、角色、建筑和主要弹窗能实例化；画面质量还需要实际窗口检查。

2026-09-21 本机验证：Godot 4.7.2 导入与场景冒烟测试通过（含真实扣费后结果面板）；Swift 抽卡集成 23 项与桥接 21 项通过；指针事件回归覆盖桌面入口、酒馆、采金进度、培养和星技；桌面原生测试覆盖 14 项断言。Apple M4 / OpenGL Compatibility 真实窗口中已操作菜单开启桌面、关闭管理窗口、从菜单重新打开酒馆以及 Command-Q 退出。测试输出图层在 `dist/godot-desktop-tests/desktop-layer.png`，并实际检查像素透明度，不把纯色背景当作透明。

## 当前限制和后续方向

当前为程序化低多边形模型，不是成品美术或 Blender 精修模型。后续可以逐个替换成 glTF/GLB，保持节点接口及权威任务状态不变。新武将暂用职业/配色变体，尚无 30 套完整独立角色资产。

暂未导出独立发行 app，运行仍依赖本机 Swift 桥接；跨平台发行、完整离线结算、模型骨骼动画、更精细的粒子/音效、完整批量培养、完整建筑种类与移动端交互仍需另行实现和验收。桌面模式不等于完整 PRD 已交付。
