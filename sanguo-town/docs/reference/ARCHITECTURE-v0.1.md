# 桌面三国·小城志｜软件架构设计书 v0.1

**设计基线：PRD v0.3「Mac M4·主公决策与分层治理版」**  
**日期：2026-09-19｜状态：架构基线与首批开发范围，不代表完整游戏验收通过**

> 一城任太守，多城托都督。玩家决定方向，系统把决策变成可解释、可保存、可复现的发展。

## 01 架构目标与版本关系

本书基于仓库 `sanguo-town/docs/PRD.md`，基线提交 `68ea158898c2a05caf0beed1fa71a6a9a4933beb`，不混用其他同名 v0.3 附件。原PRD保持不变。玩法未定稿部分以本书的“工程补充／待验证”标识，不通过实现细节悄悄改变已经确认的体验。

核心目标：单城和多城用同一套状态；治理不依赖玩家在线；预算、物资、人物、时间只有一个权威来源；任何收益都能追溯到实际事件；Mac窗口不影响模拟结果；核心在断网和不授权输入监控时完整可运行。

本轮正式进入 G0 和部分 G1：交付可编译的纯Swift核心、命令接口、分层任职与本地太守调岗、基础生产、职业经验、七天离线边界、原子快照、命令行示范和Mac窗口骨架。**不把这批代码称为完整的三城经营、自动战斗或可正式发行的游戏。** 具体实现／测试状态另见 `BUILD_STATUS.md`。

## 02 关键架构决策

| 决策 | 采用方案 | 代价与约束 |
| --- | --- | --- |
| 单机模块化 | 一个应用进程、独立规则核心 | 不建微服务、账户服务器或云数据库 |
| 技术栈 | Swift 6模式；SwiftUI/AppKit壳；后续SpriteKit表现 | Mac优先；Linux只验证平台无关核心，不验证Mac UI |
| 第一批模块粒度 | 一个SanguoCore target，按文件隔离领域 | 避免早期几十个空模块；边界稳定后再拆包 |
| 状态写入 | GameSession actor串行提交 | actor方法的提交段不跨await，防重入穿插 |
| 时间 | 整数因果时间＋现实覆盖水位 | 七天以外休整，不把现实时间直接当所有到期时间 |
| 规划 | 有限动作、确定性排序、显式授权 | 不依赖LLM；人物不同不等于读取不同隐藏信息 |
| 首批存储 | 有大小限制的JSON原子快照＋三个备份 | 原型易审计；正式大量账本阶段评审SQLite事务 |
| 对外写入 | 所有代码仅在sanguo-town内 | 不改原诗词游戏代码、站点入口和发布脚本 |

Swift Package Manager支持library、executable、test target分离；Swift actor与MainActor支持不同责任的数据隔离。[S1][S2] 本项目的线程安全还依赖命令校验和事务顺序，不能把“用了actor”当作自动获得业务正确性。

## 03 系统边界与依赖方向

```text
Mac界面 / 命令行 / 测试驱动
          │ 结构化命令、查询
          ▼
GameSession（串行、保存成功后发布状态）
          │
          ▼
GameEngine（纯规则、校验、统一事件顺序）
   ├─ Governance（权限、任职、岗位和方针）
   ├─ Economy（库存、供给、生产）
   ├─ Careers（五维、专长、履历）
   ├─ BudgetLedger（授权、预留、消费、释放）
   └─ 后续 Logistics / Projects / Campaigns / Collections
          │
          ▼
WorldState / SaveStore（版本化快照、备份）
```

依赖只能从平台壳进入核心，核心不import SwiftUI/AppKit/SpriteKit，不读取系统键盘、网络、当前时间或用户文件。外界把时间作为参数传入。渲染器读取只读快照，不按帧增加粮食。普通人物是执行者，不为每个NPC建立持续运行的线程或模型代理。

P0-R的ActivityAdapter和MarketAdapter未来只向受限入口提交已聚合数据。行情不能进入战斗种子、规划排序、人物经验或互市报价；输入统计不能提交游戏之外的操作。

## 05 领域实体与身份不变量

| 实体 | 所有权与核心字段 | 不变量 |
| --- | --- | --- |
| WorldState | schemaVersion、rulesVersion、revision、时间、国库、城市、人物、辖区 | 全局现金只有一份；ID唯一 |
| City | id、人口、禀赋、建成设施、各类库存、岗位、太守、辖区 | 资源按城市保存；劳力不超过floor(人口×0.75) |
| District | id、城市集合、都督、可调用人才池 | 城市只属一个辖区；范围变化须授权 |
| Person | id、基础属性、职业经验、当前城市、职位、锁定 | 一人一个实际职位；地点不是展示偏好 |
| Policy | 方向与继承范围 | 永续，不通过到期重复授权 |
| Initiative（后续） | 目标、权限、累计成本、终止条件 | 人事变化不重置预算和战败记录 |
| Receipt | commandID、规范化命令、提交revision | 同ID同内容返回原结果；同ID异内容拒绝 |
| DomainEvent | 因果时间、类型、参与者、真实结果 | 日志是结果，不反向成为资源来源 |

所有标识为稳定字符串。业务顺序使用稳定排序，不依赖Dictionary遍历顺序。导入先检查版本、范围、关联ID、库存、职位和额度，再准许模拟；未来版本不能按旧规则勉强运行。

## 06 官制、权限与继承

主公可任免都督、设置辖区、改变全局方针和授权战役；都督在辖区及人才池内任用太守、协调资源；太守在本城分配岗位；军团负责人执行军务。城内商贸负责人不再成为与都督并列的全局资源争夺者。

权限决策按“产品禁区→玩家锁定→上级授权交集→本角色作用域→资产当前状态”检查。预算充足不代表有权开战；统率高也不能增加权限。系统代理只执行中性安全职责，不提供名将特性或复制名将。

任职校验同时看人物状态、地点、岗位空缺与人才池。自动换任需要适配改善和冷却；不为刷经验频繁调人。跨城任命属于带旅行和交接的项目。**首批仅实现同城换任，跨城调任明确拒绝并返回未支持原因；不以瞬移暂代。**

都督和太守分别记录职务；军团指挥身份与其出征活动不是两份职位。迁移辖区和跨城交接在G2补完前不在正常入口开放。

## 07 主公命令与原子提交

公共写入口接受CommandEnvelope：commandID、expectedRevision、principal、payload。payload使用封闭枚举，不能提交脚本、任意JSON路径或直接修改库存。

提交顺序：

1. 先查回执：同ID同payload返回原回执；同ID不同payload报错。
2. 检查expectedRevision，过期决策要求重新预览。
3. 在当前WorldState的候选副本中做权限、参数和资源校验。
4. 应用全部变更，运行全局不变量检查，生成事件与回执。
5. 持久化候选快照；失败时保留原内存状态并返回错误。
6. 保存成功才替换权威状态，向UI发布新快照。

GameSession事务段不跨await；耗时模拟在其actor执行，不在MainActor执行。文件保存第一阶段为同步、有界的小型写入。未来改后台存储actor时必须使用串行提交队列或明确的比较交换，不能在await后无条件覆盖新状态。[S2]

幂等记录保存于存档，不依赖内存。原型设记录数量上限；到限时明确拒绝新增命令而不是静默删除旧ID后重复执行。正式版改为分段事务账本。

## 08 时间与确定性推进

保存 `lastWallUTC`（已覆盖现实时间）、`simulationTime`（因果秒数）、下一模拟边界、剩余分数和规则版本。运行中由平台把时间传入；核心不调用Date.now。

首批经济使用600秒批次结算，以整数千分资源避免每次取整丢掉居民口粮。调用者把时间一次推进两小时或分成多个片段，跨过的相同边界只结算一次。没有经过完整批次的时间保留为余量。**这是G0/G1固定批次切片，不冒充PRD完整的逐项目开始预留／精确事件调度。** 后续项目事件队列以相同模型扩展。

七天内：同初始状态、相同命令、同暂停策略，在线分段与离线一次补算结果相同。超过七天：正常推进到上限，现实水位推进至本次实际返回时间，休整段不补周期预算、不扣口粮、不重复领收益；回到未来正常时间继续。时钟倒退不倒扣，也不把水位移回去重复覆盖时间。

后续已承诺的有限运输／修复进入安全排空，仅完成上限之前已启动的动作，不创建下一步。首批不存在这类项目，因此不实现空壳“排空成功”。新增项目时必须追加排空测试才能开放。

## 09 经济、财政与物流的目标架构

资源使用整数千分单位，铜钱使用整数铜；上限验证防溢出。每城库存记录owned、reserved和free=owned-reserved，消费不可穿透已承诺物资。民生储备优先于加工、贸易和军事。

最终财政分为日常周转、建设再投资、专项累计毛额。父子额度不是两份钱；成功预留需同时满足现金／实物自由库存、子额度与全部祖先额度。原子预留失败不扣任何部分；消费把reserved转spent，退款只释放实际未消耗部分。卖货回款不会恢复专项历史额度。

首批BudgetLedger实现单额度的reserve/consume/release及边界测试，**尚未接入自动建设和跨城贸易，不宣称三层财政完成**。后续接入祖先路径时，所有相关账本必须在同一候选WorldState中一起提交。

城际物资通过Cargo单一归属从城市转入运输队，再转入目的城市。发运并不增加全势力实物，到货不重新发生产奖励。运费与报价在签约时锁定，实际集结地决定路程。三城样例可以验证人事和城市差异，但物流未实现前不得把全局粮食直接供给缺粮城市。

## 10 分层规划与解释链

规划器输入已知快照、政策、角色、权限和可用资源，输出标准候选动作，不直接写库存。硬约束筛选先于评分；普通官吏也必须会保供和拒绝越权。

目标频率为都督每小时、太守每半小时、军团关键阶段／五分钟，按游戏因果时间驱动，不逐帧思考。首批只支持本地太守调岗与都督同城候选补位；没有暴露建设、军事或外交假动作。

人物适配由基础能力和职业专长计算；风格只对合理方案做有限偏移。当前方案有效时保留一定惯性，避免两项评分接近时反复换岗。无资源、无合法动作时明确等待，不能空转重试。

记录“当时知道什么→为什么选它→实际提交什么→花了什么→发生什么”。关键摘要按全势力聚合，默认最多三条展示；普通生产事件不每天变成几十份奏报。预测与实际结果使用不同类型字段。

## 11 武将属性与培养：工程补充

用户随后提出要加强属性与培养。为避免旧四档能力与新五维同时重复加成，本架构定义基础五维：统率、武勇、智谋、内政、魅力（1—100）；职业经验为治理、统筹、军务、交涉四类。五维回答基础特点，职业专长回答实际经验，性格回答偏好的方法。

样例数值属于本作原创配置，不是历史人物评价。原型中太守适配以内政、智谋、魅力加权；军团适配以后另按统率、武勇、智谋映射。装备不改变人事权限、不凭空提供统筹经验。

首批成长：真实在岗并完成一个有效小时的治理／统筹后增加相应XP，每人每小时最多一次；都督不按辖区城市数乘倍。稳定运行同样有经验，不只奖励制造问题后救火。被阻塞且无有效职责、空闲和重复任免不给履职XP。等级由XP派生，首批职业等级1—10，不额外乘一套万能战力系数。

培养树、研习项目、属性成长上限与战术效果是后续独立配置工作；本轮仅落地数据结构、适配、经验与履历去重。不把新增五维字段说成完整养成系统已经完成。官职不受等级硬锁；代理能维持基础工作。

## 12 战争、收藏与主公决策的集成契约

战争将使用Campaign→Expedition→BattleResult分层。主公授权目标／对象／损耗，都督组织，将领执行；同一快照和种子生成同一战果。回放消费日志，不重新掷骰。失败签名、替代次数和累计损耗跟随战役ID，换将或改名称不刷新。

收藏使用唯一实例和常驻路径。项目完成即入账，观看动画不再次发奖。武将、名器、神驹在战败中永久保留；物品借出时只有展示铭牌，不复制可用实例。将来装备锁与人物锁共用事务。

Proposal保存生成时的依据revision、选项、真实代价和默认行为；采纳时重新校验，过时建议不直接扣费。拒绝或不处理保持现行方针，仅暂停需要新权限的专项。首批只提供方针切换入口，十张决策卡和收藏路径尚未实现，UI必须明示。

## 13 存档、损坏恢复与版本策略

SaveEnvelope包含schemaVersion、payload和完整性校验值。payload为有序编码的WorldState；校验用于发现意外损坏，不作为加密、签名或防作弊。导入文件先限制大小，再解码并验证对象数量、数值、引用和规则版本。

提交前将上一份有效快照保留为备份，轮换至三份；新主档使用Foundation原子写入。进程意外退出后只能读到有效旧快照或有效新快照；**不宣称已经验证断电硬件持久性。** 磁盘写失败不得向UI报告操作成功。

主档坏了不能自动覆盖为空档，也不静默回滚几个小时前。返回带备份入口的错误，由用户选择明确恢复。原型提供备份文件及说明，图形恢复向导后续完成。

文件路径由平台通过Application Support定位；测试与CLI使用调用者显式给的临时路径。隐私扩展的凭证、应用白名单不进入游戏存档。旧规则迁移以版本映射实现，没有实现的迁移拒绝加载并保留原文件。

## 14 Mac桌面与生命周期

SwiftUI管理界面、AppKit生命周期、MenuBarExtra入口共享同一GameSession。Mac骨架保留Dock恢复入口，提供主公府、城市概览、人物履历与方针切换。菜单栏操作只在用户点击时打开窗口；状态变化不调用激活、弹窗或系统通知。[S3]

第一批不制作完整像素街景，使用文字与轻量视图显示真实模拟状态，避免用漂亮动画掩盖空核心。SpriteKit未来仅负责当前可见城市和战斗回放；隐藏后停止渲染，模拟不依赖帧回调。

睡眠不阻止系统休眠，不声称合盖持续运行。当前快照按周期和关键命令保存；恢复时补算。彻底退出前等待已经排队的保存；保存失败留在应用显示原因，不能立即终止导致假成功。UI在MainActor，纯模拟与文件写在独立actor。

macOS部署目标沿PRD暂定15；具体M4型号、内存和安装系统仍待用户实机确认。没有macOS SDK的Linux构建只覆盖核心和CLI，Mac目标必须单独在Xcode环境编译验收。

## 15 隐私、安全与网络

G0/G1没有网络访问、输入监控、屏幕读取、行情API、自动化办公或真实下单。仓库不能保存券商令牌、工作内容、用户持仓或键盘明细。将来的权限失败降级为纯游戏，不要求关闭系统保护。

LLM不在核心依赖中。未来接入也只能提出可验证的游戏命令或润色事实摘要，不能运行shell、读工作文件、控制券商或改变已结算结果。文案不能因为语言模型说“已获得”就生成资产。

公开仓库的演示数据均为虚构游戏状态。开发版不自动遥测；用户手工导出的诊断包须剔除所有现实联动信息。

## 16 测试策略与真实完成度

| 测试层 | 核查内容 | 不能代替 |
| --- | --- | --- |
| 原静态检查 | PRD编号、配置数量、部分算术 | 任何运行时游戏测试 |
| Swift单元测试 | 状态不变量、命令幂等、权限、固定点生产、XP | 完整经济平衡与可玩性 |
| 保存集成测试 | 往返、损坏拒绝、备份、写失败不提交 | 真实掉电和多设备冲突 |

## 18 风险、降级和验收关卡

最大体验风险是自治包办乐趣；解决办法是让主公的方向和人选影响实际方案，而不是制造多余审批。最大实现风险是不同模块各扣一次钱、离线重复覆盖、角色在两地同时生效；用统一事务和确定性测试控制。

原型快照会随历史增长，设文件与对象上限，超过明确报错；正式版改分段账本／数据库。先测三城，不把所有NPC各自做全局搜索。规划失败只暂停相应目标，不能用“重新初始化存档”恢复。

任何负库存、重复资产、违反锁定、损坏存档静默重建、失败保存仍提交、无法退出、抢办公输入焦点都属于发布阻断。对外发布还需素材来源、签名公证和M4能耗验证；本轮代码不等于这些关卡通过。
