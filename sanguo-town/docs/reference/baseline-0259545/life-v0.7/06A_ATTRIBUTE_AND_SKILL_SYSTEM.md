# 06A 四维、标准战法／特技与数据扩展

**PRD v0.8.0。固定沿用22技能与7原语；仅行政作用域改为实际劳动取得的租约。数字与角色引用由hero-town-v0.8.json及锁定技能库提供。**

## A.1 三个独立层，不再把姓名当效果

人物记录只存id、name、baseAttributes、skillIDs、jobXP、office、location和造型引用。属性决定基本适配；战法/特技决定专长；官职、任务和真实位置决定这些能力作用于谁。姓名只用于展示、身份、招募和历史，不作为生产、折扣、任用或护送效果的判断条件。

四维采用政治、智力、武力、统率；“智商”在界面统一显示为智力。内部键保留administration/strategy/valor/command，避免无必要改名。每项整数0—100，常住武将取30将明确配置；有效值=clamp(基础+本人合法装备,0,100)。不保留第五项魅力参与新规则；交涉通过政治/智力加权与通商技能表达。

任何基础配方和自动保供都不要求特定名将或技能。缺少任一特定非开局武将仍能正常吃饭、建房和运输。政治高不会凭空加粮；武力高不会让所有农田增产；统率高不允许突破主公编制与预算。

## A.3 统一劳动公式和任用评分

本人加成=min(1000,max(0,A_job-50)×20)。职业熟练度L1—L5贡献(L-1)×100基点。主管加成=min(500,max(0,A_job-50)×10)；主管A_job取其本人的四维，不取下属的。都督加成先乘50%向下取整，再与本城太守取最大值。不能叠成两次行政加成。

最终人工率=clamp(10000+本人加成+熟练度+主管加成+适用能力+设施加成-可选低满意惩罚,8000,14000)。适用能力合计上限1200基点。设施沿用既有明确定义；粮食保护等规则先于效率比较。工作量baseSeconds×10000，以剩余整数工作量推进，完成时间向上取整；不按动画帧结算。

太守不永久退出生产；每600秒窗口实际完成30秒行政才取得600秒组织租约，入睡/卸任即时失效，详见05章。本人工作时排除自己的主管来源。v0.8都督、军团统帅未启用；以下军务公式保留为技能库定义而非本版可用玩法。实际统帅做训练时，他就是该训练任务的人工贡献者，用guard权重和本人熟练度，读取commander的training_rate_bp；训练不再另领太守/都督的主管人工加成，避免同一身份重复放大。训练的有效能力与其他人工加成仍受1200/14000上限。

太守基础任用分=floor(政治50%＋智力30%＋统率20%)；都督=floor(统率40%＋政治40%＋智力20%)；统帅=floor(统率60%＋武力30%＋智力10%)。这些只用于推荐，不是任官门槛，不代替出征评分。行政调动使用基础属性，不因换武器来回换太守。

方针适配不再出现“安民时荀彧+8”。用JSON中的policy_fit_job_weights_bp，对候选太守能提供的各工种主管属性与work_rate_bp计算加权效果；F=floor(10×Σ权重×效果/(10000×1700))，0—10。太守总推荐分=基础任用分+F。非人工收益如报价/侦巡在推荐卡另列，不隐性加分。代理、锁定、调任总改善≥8与冷却沿用05章。

## A.4 1—5项技能：技能数量不是日常操作数量

每位武将必须1—5个不同skillID，特色技能最多1个且占用这5个名额。不创建普通居民；30将初始技能见06章，定义统一在hero-system JSON。数量多不代表每项同时在所有岗位生效；当前无适用场景的卡片灰显并解释。

当前版本所有技能固定等级1、自动生效；不加技能强化材料、体力、随机触发率、洗练或手动技能按钮。工种jobXP继续通过真实履职积累，不占1—5个技能位，不提升基础四维，也不自动解锁新战法。skill_learning/skill_reroll/skill_consumables/manual_casting均为false；后续增加授业需要独立规格，开发不得擅自添加获取途径。已有名将招募、装备和培养记录照常保留。

“战法”在本版仅作用于有限护送结算；“特技”作用于经营、整训、巡逻等已定义流程。没有完整战场时，不展示“八阵困敌”等没有结算入口的空技能。本版不声称已实现主动战斗和战术时间轴。

## A.5 作用域、触发点、叠加和上限

|效果原语|触发快照|只允许来源|合并后的上限|
|---|---|---|---:|
|work_rate_bp|人工阶段开始|实际执行人、有效太守、有效都督|1200基点|
|purchase_discount_bp|新采购合同报价|实际经办人、有效太守、有效都督|与属性折扣合计1000基点|
|patrol_speed_bp|巡逻/追逐新路段开始|实际巡兵、有效太守、有效都督|2000基点|
|training_rate_bp|训练人工阶段开始|实际统帅|1200基点|
|escort_score|护送实际出发|实际统帅|10分|
|wounded_reduction_bp|护送实际出发|实际统帅|3000基点|
|happiness_rise_extra|餐窗开启|有效太守、有效都督|2点|

能力记录必须带metric、event、roles、family、value，以及可选jobs筛选或requires_coverage_bp。未知字段、未知event、无定义metric、非法参数范围一律拒绝新规则，不执行任意脚本或字符串表达式。

先过滤真实任职、辖区、位置与对应任务，再按范围折算：都督50%且向下取整，其余100%。同metric+family跨自己/太守/都督所有来源取最大；不同族相加后封顶。同一sourcePersonID不得以两种身份重复传入，一城不能传入两个有效太守。例：本人农桑400、太守农桑400、都督农桑200，最终农桑仅400，不是1000。600与400的不同族可加1000。整点效果1×50%向下取整为0，UI显示本职位折算为0，不暗中补1。

有效太守须完成交接、在城且adminLease未到期，租约实际执行者为sourcePersonID；不得把任职标签当永久光环。执行人等于sourcePersonID时排除该主管来源；有效都督须管理该城市且当前位于自己辖内某城，不在城际旅程；统帅必须属于本次军团/行动快照。完成的过去阶段不再重新验证当前职位。权威上下文只能由世界状态生成，不允许客户端传eligible=true绕过权限。

普通资源采购：实际经办人、太守、都督按merchant权重算A，各自max(0,A-50)×10、上限500；都督折半，各来源属性折扣取最大。属性折扣＋标准技能折扣总计≤1000。总应付=ceil(牌价整单×(10000-折扣)/10000)+运费。合作协议是另一合法报价，两者取较低，不连乘。人物、唯一物、猪、板车和餐饮销售均不应用此折扣；大额也不按每份先取整。

巡逻速度=基础48×(10000+有效巡逻技能+合法道路加成)/10000；这只适用于patrol/pursue路段，不修改普通空载、负重或板车公式。步速属于世界任务，不因画面帧率改变。军团训练原语在v0.8不触发。城内守备演练属于guard普通人工，不传commander角色，不读取training_rate_bp；仅本人普通劳动和已建演武场加成有效。

后续军务参考护送分按历史06章的兵数、训练、城防和统帅四维子式，加标准escort_score。伤兵=ceil(基础伤兵×(10000-减伤)/10000)。首次出发保存全部技能结算与装备快照，一次行动只应用一次；重播、重新读档不重新掷骰或释放技能。

餐窗开启时保存主管与恢复技能，截止时用实际覆盖判断是否≥95%，达不到则额外恢复0。技能只改变向实际目标T恢复的上限，不提高T、不把没吃饭记为吃过、不直接消除短缺。

## A.6 快照、可解释性与边界例子

每个效果快照保存contentHash、skillID、definitionVersion、sourcePersonID、sourceRole、eventID、metric、family、rawValue、scopeScale、retainedValue与capResult。显示“属性贡献/熟练度/主管/特技/设施/限制”分项，不出现没有来源的战力。重复同族未采用时标“已被更高同类覆盖”，无职、在途、不同工种时标无效原因。

人工：准备阶段开始与收尾阶段开始分别快照；中途换太守不回算当前阶段，尚未开始的下一阶段读取新有效值。被动等待永远不读人工倍率。行走每新路段快照，报价每新合同快照；旧出征、旧义务沿其已固定版本收尾，不能为更换技能刷新预算或重算原料。

算术反事实夹具（不是可入库居民）：厨师四维50、L1、无技能，无设施/满意惩罚；荀彧实际行政租约有效时A_cook=floor(94×0.6+88×0.4)=91。主管410，庖厨400，王佐600，最终rate=11410。家常饭准备ceil(30×10000/11410)=27、被动30、收尾ceil(10×10000/11410)=9，总66秒；仍消耗粮1木0.25、只产4饭。相同属性技能的任意合法人物结果相同；取消主管全部技能的反事实rate10410，总29+30+10=69秒。

鲁肃采购10粮：A_merchant=85，属性350，通商500，合计850。ceil(40×0.915)+2=39铜。名为鲁肃但没有通商仍按属性350算41铜；没有任何合格来源则42铜。报价建立以后换人不会把39改成41。

赵云30人训练1城防1：基础45、属性14、护送4=63；伤兵5用一身是胆2000基点得到4。关羽同兵力/训练/城防：45+14+护送4+武圣6=69。同四维但零技能的反事实人物都是59。上述无技能反事实用于测试，不是可入库的武将定义（武将入库仍至少1技能）。

## A.7 扩展、迁移与反向测试

新增普通武将只增加四维、1—5个skillID、造型和合法招募配置，不改生产/战斗计算器。新增特色技能若可由7个原语表达，只加技能定义、人物引用、UI文案/图标和测试向量；新增真正的新机制必须增加原语实现、快照/互斥/存档/测试后再开放。不能声称任何未知机制都能“完全不写代码”。

v0.8只创建独立新档，不迁移旧居民或已承诺订单。旧版数据和快照继续交给旧引擎；技能库源文件不可原位修改来污染旧存档。v0.8更高补丁也必须固定旧订单快照和显式升级版本，不能按姓名重复赠技能。

新输入拒绝：武将0技能或6技能、重复ID、未知技能、两个特色、重复来源、四维缺失/超界、未知效果、非法触发点、未经实现的学习/主动施放。新快照变化不污染旧快照；只读界面不分配技能或修改四维。

旧参考程序hero_reference_v071.py仅校验历史算术，不能代表本版租约、四份配方与全武将生活验收。v0.8静态检查见validate_hero_town_v08.py，运行与人工测试按09章单独执行并记录engineCommit。
