# 02 人物任务、物流、作息与饭食

## 2.1 三种时钟，不许混用

WorldState.simulationTime为单调Int64秒。LifeState.epoch在新开局或明确迁移时设置一次，lifeElapsed=simulationTime-epoch。正常1现实秒=1模拟秒；growthDay=floor(lifeElapsed/86400)。城内作息cycle=floor(lifeElapsed/2880)，phase=lifeElapsed%2880。打开窗口、换显示器、调帧率不改epoch。一个48分钟作息周期不是一个24小时成长日。

晨[0,240)、昼[240,1920)、暮[1920,2160)、夜[2160,2880)。昼夜亮度在边界前后各60秒线性插值，只影响城景，不改变世界资源。昼夜基于模拟时钟，不默认跟随用户真实时间，否则只在白天上班的用户无法看到夜巡。

日班在晨间起床、取餐、通勤；[240,1920)接生产新任务；暮间只接受能在2160前安全完成的收尾、取餐及短程交付；夜间回家。班次变化不取消在制物，不瞬移工人。无法在夜前完成的人工工作保留进度并在安全节点暂停；被动生长与发酵继续。出发前预计返家超出班次的非必要远路任务不派发。

服务班覆盖[0,2160)，人员错峰；一个厨师每天总工作上限仍为1920秒，不能由于“服务班”变成全天劳力。日巡和夜巡是不同agent，夜班覆盖[2160,2880)及前后各120秒交接，白天睡觉。首版无玩家必须排的轮班表，太守自动保持至少一名夜巡与一名基本做饭/取水兜底。满足上限以后“有任务但不再接单”是合法休息，不允许额外发工作收益。

## 2.2 居民、名将、士兵：一人一个ID

新开局16名成年常住居民=荀彧1+普通居民15。名将也是会吃饭、有位置的居民实体，但其人物档案另存；以personID关联，不能再生成一个“名将代表”重复占据城市。正式办公、做饭、搬运、研习都占劳动时间，同一时段只能做一种。

常住人口每城上限150（含已定居名将），在城军团最多90人，外来访客12，小贼最多1，总253不超过256个可调度人物。军团志愿者是来自外部的独立招募来源，不从居民数字再复制一次；普通居民转军职必须显式迁移实体和消费账户。第一版自动征募采用外部志愿者，居民不被擅自征走。

渲染48/96/160档只是可见上限。其余真实人物仍按同一任务和时间线工作，只不提交完整骨架绘制。人物不足不补假人。城内所有生产任务必须绑定实际workerID，不能用“代表人数4”凭空代表40份劳力。动物实体单独上限32，绘制上限24。

## 2.3 最小任务状态机与锁

工作订单：WAIT_DEMAND → WAIT_INPUT/WAIT_WORKER/WAIT_CAPACITY → RESERVED → WALK_TO_SOURCE → LOAD → CARRY → UNLOAD → WORK → PASSIVE → FINISH → COMPLETE；不需要的步骤跳过。所有跳过必须按taskType白名单，不靠UI选择。工人通勤/睡觉/巡逻同样有行为任务，但没有资源产出。

父加工单可以等待多个供货子单；父单没有输入时不独占工人，避免所有人等待材料而没有人搬运。设备只能在输入就绪并即将开始准备时锁定。必要的输出容量允许提前预留，不允许超过容器容量。

一个agent只有activeTaskID；任务中至多一个独占工种。站点锁、源库存预留、目标容量预留、物品唯一锁、设备锁分开。任务冲突以优先级、截止时间、创建顺序、ID字典序决胜。优先级提升只影响未开始任务；正在搬货的人先交付或安全退回，不把货物变没再接新单。

所有资源进入sourceStock、sourceReserved、carried、destinationStock、WIP、consumed之一。reserved是stock内部占用，不计两份总量。将源库扣除与carried增加放在同一事务；carried扣除与目的库增加也同事务。完成事件ID只结算一次。显示动画不得调用加粮/扣料方法。

## 2.4 搬运口径

空手48地图单位/秒；负重32；推车28。步行挑夫容量4体积，板车12。装货10工作秒，卸货10工作秒。路程用当前固定道路图的欧氏边长之和；物理像素、桌面缩放不进入路程公式。行程秒数向上取整。普通居民共用基础速度，名马只影响携带该马的具名人物的非载货个人出行，不能给所有物流自动加速。

标准运单一次只装一种资源。数量=min(消费者缺口、源可用量、运输剩余容量、目标可容纳量)，内部mU向下取整；必须>0。货袋最小可视批次为1000mU，末尾不足一份允许显示半袋及确切数字。一个任务可搬4袋粮或2捆木，不是每单位生成一名新居民。脚夫可拆源批次，派生lotID必须保留originLotID。

板车是1辆唯一工具，占用1个挑夫。生产一辆车消耗木构4、器材1、木匠300工作秒；初始没有板车。工具在造完/采购到货后才可使用；出借给他人之前必须回到车站。不设车损坏或每日维修。

装载后资源离开源库。卸货完成前目的地不能消费；目的地容量早已预留，新的采购和生产不能挤占。目的地被删除/锁定时不丢货，改为返源；源已满时进入该来源专属返货缓冲（容量等于发出的该批体积，不可用于接新货），产生一次合并提示，不凭空扩大常规仓储。

来源选择：先本工作点现货，再同建筑可用库存，再同城最短路未预留货源，最后授权的跨城/外购。已有厨房订单允许田边直接送厨房，不强制先经过粮仓。食材要先变成合法输入类型；稻谷不能直送灶位冒充食粮。

### 物流黄金算例

源有8粮、目的0；预留4后源stock=8、reserved=4、free=4。人已在源处：t=0开始装，t=10源stock=4、carried=4；负重路程960单位，t=40抵达；t=50卸完，carried=0、目的stock=4。整个过程粮总量8；t<50目的不准吃这4粮。画质48人与160人模式此记录完全相同。

## 2.5 就餐需求与分配

每个常住居民每作息周期两餐，每餐1人份；时点phase=600、1980。窗口提前180秒开配送单，餐后允许180秒迟到缓冲。消费者名单在餐点锁定，新到居民从下一餐计；每人每mealID最多消费1000mU，不重复吃公共饭和口粮。

家常饭、菜饭、肉菜饭各一份满足一餐；肉菜不是额外吃第二份。质量分别40/70/100。应急食用口粮质量30。酒、肉料、稻谷不能直接作为居民的一餐。饮水已包含在饭菜配方；第一版不再对居民另扣一份“饮水费”。做饭缺水显示缺水，不把饭菜覆盖算成已满足。

餐前食品配送优先于外售、额外军需和收藏。住宅/饭馆餐位有收货容器，堂役放下后绑定这一餐。可使用家中送餐替代堂食，餐位不足不导致居民明明有饭却长期饿着；堂食是可选表现，不是效率惩罚。堂食每座4席、吃饭45秒；无座或路程超过120秒，自动改送住宅/官署。夜巡使用提前送到岗亭的晚餐份额，不在夜里到处找厨师。

窗口截止时记录expected、served、foodKind、consumerIDs。迟到前已有供给的居民正常吃，不等全城凑齐；截止后未满足数量记短缺，下一餐是新订单，不补发过去的免费饭，不重复惩罚。晚到食物仍是当前合法库存，可供下一餐，不能报废或自动算已经吃过。

## 2.6 粮食保护不是固定分配百分比

设N为常住居民数。民用食物等价E=合法民用熟食人份+4×民用食粮+3×民用稻谷+民用可直接食用口粮+已经投入并锁给民用餐食的WIP最终人份。只统计一次；军用封存、已出售、未到城的外购不计。原料在搬运中仍属于本城民用链，按carried统计但不算“立即能吃”。

正常民食底线为2周期，即4N人份。额外军需、喂猪、酿酒、外售、收藏用粮都要满足操作后E≥4N。基础做饭和民用搬运是同一营养存量的转换，不能因保护线阻止。厨房目标为接下来2餐=2N份；主粮生产目标为4周期=8N份。实际接近库存目标时停止接新单，不制造过量再丢弃。

优先级顺序：正在发生/下一餐民用供给 → 已在外执行军务所需已承诺补给 → 民用2周期余量 → 已有动物下一段和必要补种 → 已批准非战斗军团维持 → 菜品改善 → 新增扩军与远征备料 → 出口、酿酒、可选收藏。已经合法承诺并离城的货物不能瞬移挪回；不要用新保护线追溯取消旧合同。

供给充裕时，菜品目标按方针：安民肉菜50%+菜饭25%，兴商肉菜25%+菜饭25%，兴业菜饭50%，备战全部家常饭，均衡肉菜25%+菜饭25%；剩余为家常饭。此为目标，食材不足无条件退到可制作的低档饭，不能为了凑肉菜饿人。每餐按轮换起点(cycle+mealIndex)%N分配更好的菜，避免低ID永远吃肉。用户不需要填写配比。

## 2.7 满意度公式及缺粮恢复

每餐截止后计算一次。餐食覆盖C、质量Q取最近4次已截止就餐窗口；不足4次只取已有次，不能用还没到的餐作零分。C=100×累计served/累计expected；Q按实际食用份数加权，全部无人吃到则Q=0。N=0不生成就餐事件，不除零。

住房H=100×min(有效住屋容量,人口)/max(1,人口)。清洁D=clamp(40+10×近一周期完成的不同清扫地点数,40,100)，每地点只计一次、总共6个地点。治安S=clamp(40+40×最近完成夜巡路线覆盖率+5×城防街区等级+2×街巷等级,0,100)；首个夜晚完成前取60。休息R=100×在最近夜间获得至少600秒连续休息者/应休息人口；夜班人员用对应白天连续600秒休息，首轮取100。

T=(40C+10Q+15H+10D+15S+10R)/100，取整数四舍五入。满意度初始70；每餐向T移动，下降最多5，上升最多3；荀彧实际任太守时上升上限+2，即5，不改变T。下限0、上限100。基础饭且C/H/R=100、Q=40、D=S=60时T=84；70首次升到73，荀彧任职升到75。

连续就餐短缺会降低满意度；不会死人、逃散、暴动、烧城或丢收藏。满意度<50只对可选工程和非必要军团训练的工作rate减1000基点，最多减10%；农业、取水、做饭、搬运、住房修复、巡逻及必需供给不受惩罚。低于阈值和食物短缺各自不得再次叠罚。

每43200秒进行一次新增定居检查：最近4餐覆盖≥95%、满意度≥70、至少2个空房位、迁入后民食E≥4(N+2)、人口+2≤150，才接纳2人家庭。不满足就跳过，不积攒待补发家庭。住房为邀请名将预留的床位不能再分给迁入家庭。满意度恢复自动进行，没有点击安慰居民的任务。

### 16人基础饭核算

每周期32份饭，需2批cook_basic：食粮8、水4、原木2；普通厨师人工150秒，被动120秒，灶位基准总占用270秒。昼间可生产窗口1680秒，足够完成，真实通勤/取料/进餐仍须算入人力。每现实小时1.25周期，需40份饭、10粮、5水、2.5木。该算例只是固定配方算术，不声称完整物流、种植或90日平衡已经通过。

## 2.8 短缺自动恢复、队列上限和原因码

每30秒评估需求，不必每帧运行。待办上限2048/城，达到上限先合并同需求，不删已承诺任务。系统保留至少2名能接基础搬运的非专职工人；这2人可以空闲或兼工，但新可选工程不能永久占满二人。人口极少时厨师/农夫自取料，不要求凑齐20职业。

恢复顺序：停止新的粮食出口/酿酒/额外扩军→用已有低档饭或释放的民用口粮→厨房改基础饭→调可空闲居民到取水、种粮、搬运→使用本期已授权应急采购额度→必要时暂停可选工程释放劳力。欠款、传送、免费资源均不是恢复措施。

统一原因码：NO_SOURCE_STOCK（没有原料）、NOT_DELIVERED（在城但未送到）、NO_WORKER（无空闲合资格人）、OUT_OF_SHIFT（休息中）、NO_ROUTE（道路不通）、NO_INPUT_SPACE、NO_OUTPUT_SPACE、NO_CASH、RESERVE_PROTECTED、PAUSED_BY_PLAYER、WAIT_PASSIVE（生长/发酵）、TARGET_SATISFIED。主屏翻译成一句可读原因，不统称“效率不足”。清洁和巡逻均由现有工人实际完成；不能为抬满意度每30秒直接写满D/S。

## 2.9 同时间事件排序

对时间t：先推进上一段劳动/生长；再按taskID提交完成与到货；再处理班次边界和餐点名单；再处理本餐实际消费及窗口截止；再结算满意度、迁入和地区到达；最后重新分配任务。恰好在就餐截止时完成卸货可以供应该餐；刚迁入的居民从下一餐算。随机事件单独使用保存的worldSeed和cycle，不依赖系统随机数、帧率或遍历哈希表顺序。

跨越离线区间使用同一事件优先队列，不用“最后一刻产率×时长”。正常补算上限30现实日；超过后只收尾已完全承诺的有限任务，停止新的餐食扣除、生长周期、工资/预算周期和小贼事件。离线剩余真实时长不足，不能提前完成收尾。恢复后沿用原方针，无逐城续约。
