# 01 资源、农业、养殖与加工

**规格版本0.6.0；目标运行规则life-0.6；本文件不是已实现声明。** 数值由`../../spec/life-v0.6.json`唯一确定，时间均为模拟秒，数量表中的1份=1000内部单位（mU）。所有农业、配方和人物数值是原创游戏参数，不是三国史实或现实农学数据。无加成、无缺料、无夜间等待时的数值才是“基准”，界面不得把基准当预计到货时间。

## 1.1 资源边界与单位

首版17种可堆叠资源：稻谷paddy、食粮grain、时蔬vegetables、草料fodder、肉料meat、清水water、原木wood、木构planks、石材stone、铁矿料ore、铁料iron、器材tools、家常饭meal_basic、菜饭meal_veg、肉菜饭meal_meat、行军口粮rations、酒wine。

稻谷必须脱壳才成为食粮。粟的收割工时已包括脱粒，直接产出食粮；不再额外收一次加工费。原木不是木构，矿料不是铁料，普通熟食不是军需库口粮。铜钱是国库账，不是挑夫搬运的资源。人物、活猪、坐骑、兵器和开城木印是有唯一ID的实体，不混入普通库存枚举。

每份原木、木构、石材、矿料占2体积；每份饭菜或口粮占0.25体积；其余占1体积。仓储按全部物资体积之和约束，不能沿用旧版“每种资源单独有一整仓容量”的实现。液体必须使用桶/坛视觉；活猪是引导运输，不允许画成粮袋。

第一版无自然腐败、保质期、疾病和随机减产。不得由开发自行添加饥荒死亡、牲畜死亡或每日维护税。已成熟作物可以等工人，暂停不会腐烂。后续扩展要更换参数版本并单独迁移。

“120分钟成熟”不包括播种、浇水劳动、等待水、收割和运送。有效生长可跨夜；农业劳动只在实际班次执行。工种和太守的劳动加成只加快劳动步骤，不能把120分钟生长缩短。水利街区在life-0.6中解锁水稻及增加工作点通达性，不再叠加旧版按小时发粮或无定义的额外产速。

### 唯一作物状态机

EMPTY → SOW_RESERVED → SOWING → WATER_0 → GROWING_1 → WATER_50 → GROWING_2 → RIPE → HARVESTING → OUTPUT_WAIT → EMPTY。

1. 空床由太守根据订单选作物；播种前预留第一桶/批水和田边输出体积。种苗来自农庄固定留种圃，不作为可售资源；净产出表已扣除留种部分。留种不能拿去吃、出口或喂猪；无另行随机扣种。
2. 播种完成后浇第一批水。浇水完成才把有效生长设为0并开始计时。
3. 累计到50%时停止生长，产生第二次浇水任务。所需清水实际到田边、农夫完成20秒劳动后继续。水不足只暂停，不退回苗期。
4. 100%只代表成熟，不发放可用资源。农夫完成收割才在田边产出唯一批次。此时资源在田边，粮仓还没有收到。
5. 田边货物移走或有足够剩余输出容量，才允许下一轮播种。取消等待播种不扣资源；取消已播种作物仅允许“保留并暂停”，首版不支持铲除换种。
6. 同一田床最多一个周期。播种、两次浇水、收割各有taskID，输出仅允许一次；关闭窗口不产生额外周期。

### 水稻无等待算例

从t=0开始播种：t=60播完；t=80第一次浇水完成；t=3680有效生长达到3600秒；t=3700第二次浇水完成；t=7300成熟；t=7390收割完成，田边出现32稻谷。之后另加取货、步行、卸货和8批脱壳。此算例刻意关闭班次限制，作为单位测试；普通游戏跨夜时要插入实际等班时间，不能宣传“7390秒必定到仓”。

基本手工具是居民入城时声明的不可交易随身工具，本版无耐久与换工具日课。库存tools是工程/军需消耗品，不是每挥一次镐就扣一箱。伐木产出后补植任务必须登记，不因工人转岗消失；树木没有补植就不开始再生。前台表现伐倒、整理木捆、补植，后台只按任务结算。

每个采集点输出缓冲24体积，井边24体积。输出容量已被预留则不再开新采集任务；缺运力应显示“等待搬运”，不能无限产出再删除溢出量。自采无铜钱奖励。采集者忙于工作时由挑夫运输；无空闲挑夫时采集者可以完成本批后自运，运输期间不能继续采集。

## 1.4 养猪：成长实体，而非肉料计时器

普通猪与收藏马使用不同entityKind。牧栏最多8头。幼猪20铜，通过本城集市的一次采购合同到货，行程300秒；合同扣费后生成在途animalID，到货才进入牧栏。取消未发货合同全额释放；已发货只可到货安置，不能反复取消刷猪。第一版繁育关闭，无成对繁殖或隐性再生。

每头幼猪需要6个成长段，每段2880秒有效成长；每段开始需实际投入1草料、0.25食粮、1清水，牧工照料30秒。共6草料、1.5食粮、6清水、180秒照料，净成长17280秒/288分钟。照料可跨多个工作日排队，投入不足不成长、不倒退、不死亡。段内已喂饱的被动成长可以跨夜，不能再次收费。

MISSING_PEN → ORDERED → IN_TRANSIT → JUVENILE → FEED_WAIT → GROWING(n=1..6) → READY → LED_TO_BUTCHER → PROCESSING → CONSUMED。

出栏由需求拉动：本城肉料低于两轮菜品计划所需、民食储备达标、厨房或有效买方有订单时才出栏。首批肉食工90秒处理一头ready猪，唯一动物实例变成8筐肉料。动物在PROCESSING是不可食用在制品，不在猪栏/菜谱中重复出现；普通表现是关门加工与肉筐交付，不做血腥动画。出栏之后不退回活猪；系统错误通过事务回滚，不靠复制实体补偿。

新增猪的许可需同时满足：牧栏空位、每头剩余成长段所需饲料已纳入预测、扣除下一段0.25粮后民食保护仍满足、可用铜足够。短缺先暂停新增采购，不卖收藏坐骑；已有猪安全等料。草料零时可以补种牧草，不自动按未定义比例拿食粮替换。

每个设备同时只处理1批；灶位不能同时煮饭和酿酒，酒槽单独占位。铁匠可以在冶炼被动等待时去锻造，但只能承接一个人工阶段。无夜班的加工在准备途中到夜间安全暂停；进入炊煮、熔炼、发酵或风干以后，被动计时继续，收尾必须等有人。

### 通用加工状态机

REQUESTED → WAIT_INPUT/WAIT_STATION → RESERVED → DELIVER_INPUT → PREPARE → PASSIVE → FINISH_WAIT → FINISH → OUTPUT → CLOSED。

开准备工序前，输入必须全部在该工作台，并预留净产出的容量。准备开始将整批输入移到WIP，准备完成才记作配方投入；取消仅支持尚未开始PREPARE的订单。已开始加工只能暂停/续行，不能退款后保留成品。收尾结束一次性发放输出，并释放设备。PASSIVE=0直接进入FINISH_WAIT；未声明副产品不得自行添加。各资源按照输入配方与输出配方独立核算，不把“原木3变木构2”误报为丢了一份相同资源。

### 同一袋粮的两个合法去向

居民链：田地→稻谷批次→碾米位→食粮→灶位→饭菜→饭馆/住宅→食用。军需链：食粮→制粮台→口粮→军需库→营地消费或出发装载。每次转运都有订单和执行者，输入食粮不再保留在原仓。饭菜与口粮转换一律不允许；紧急居民直接食用已释放的口粮是“消费口粮”，不是再生产一份家常饭。

## 1.6 农牧与加工的自动需求上限

食品生产以02章的民食保护和下一餐订单为先。粮食生产目标为4个作息周期的居民饭食；肉/菜目标为未来2次就餐的目标菜品；草料目标为现有动物全部剩余成长段加2个照料周期；清水目标为下一餐与现有作物下一次浇水，加12桶缓冲。超过目标不新播/不新购猪，已经成熟与在制的批次允许完成并入缓冲。

酒和出口商品只为外部有效需求生产。木构、器材先满足已授权工程阶段和军需订单，再保留木构8、器材4的城内周转库存；铁料保留6、原木保留16、石材保留8。不得通过每30秒重新下同一需求制造无限队列。相同消费者+资源+交付窗口为唯一需求键。

谷物选择：短缺时空床优先粟；水稻已解锁、稻谷脱壳位可用且清水能供应两次灌溉时，按当前方针的农田配比选择。安民/均衡至少一半床种主粮；其余方针至少三分之一，向上取整。草料/蔬菜无需求时剩余空床保持空置，不强行满种。具体菜品优先级与人口需求在02章，太守建设和排岗在04章。

## 1.7 冻结与扩展

这版不含小麦磨粉、盐、油、布、药、食物腐败、牲畜繁育；相应按钮和空配方不得出现在正式菜单。加工路径及作物时间可以平衡调整，但需整体变更spec_version、重算02章的16人餐食算例及验收向量；不得只改界面倒计时。
