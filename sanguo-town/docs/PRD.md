# 01 产品定位与不可退让的原则

## 1.1 一句话定位

一款可以长期留在Mac桌面的轻量三国养城游戏：玩家定城市方向与发展边界，太守组织城内建设，都督协调城市群与军团。玩家在工作间隙看见城池持续变化，而非逐项管理生产任务。

## 1.2 需求优先级

| 优先级 | 必须交付的体验 | 不得以什么代替 |
| --- | --- | --- |
| 第一 | 城池有真实、持续、可辨识的成长 | 资源数字增加、无意义换皮、动画循环 |
| 第二 | 玩家操作轻，日常长期自治 | 限时派单、逐项审批、每天收菜 |
| 第三 | 军团随城市承载能力逐步扩大 | 开局送满编、无限扩军、刷关涨战力 |
| 第四 | 人才与收藏有归属和用途 | 独立打卡系统、强制碎片养成 |
| 第五 | 桌面陪伴与现实联动 | 高频行情任务、强迫打字换产量 |

## 1.3 产品边界

城池、人物与唯一收藏永久保留。不设月末结算清档、强制转生、连续登录奖励、限时绝版、离线偷城、永久死亡或必须实时救场。城市发展可以达到稳定状态，玩家有权不扩张、不打仗、不继续解锁新区。

轻量不等于没有取舍。已经批准的工程会占用资源、劳力和时间，战争可能损失授权军需；这些代价由决策产生，不由玩家缺席产生。不得为增加黏性而制造必需维护的麻烦。

# 02 核心循环与玩家贡献

## 2.1 主循环

**看城与变化 → 选择下一阶段方向 → 太守／都督持续实施 → 建筑、街区、居民与营地发生变化 → 回看成果或调整方向。**

每项重要决定必须留下三条可追溯关系：决定了什么、部属实际做了什么、城池因此改变了什么。系统不把随机奖励或继承资产冒充玩家的经营成果。

## 2.2 一次决定换来一段自主发展

例如玩家选择“城南兴商、暂缓额外扩军”，太守自行比较仓储、商铺、住房和原料准备的顺序，在预算内采购、分工、建设并维护运营。不会随后逐项追问是否买木、是否派工、是否收货。

一个方向可以持续数天到数周，完成单个项目不终止方针。当前目标达成后，部属在同一授权下做合理维护、改善和人才培养；需要改变城市性质或扩大版图时才提出新决策。

## 2.3 观察也是完整的游玩方式

打开城景、看居民活动、对比旧城、欣赏收藏，不获得额外经济奖励，也不消耗行动点。玩家可以什么都不点就离开。可选深度管理不会成为正常推进的隐性要求。

# 03 版本范围与内容层次

## 3.1 开发切片与长期版本分开验收

| 层次 | 范围 | 完成判据 |
| --- | --- | --- |
| S1可玩切片 | 一城、真实建筑、施工、太守自治、简明城景与存档 | 首次方向选择能连续推进至少三项合规建设，画面对应真实状态 |
| P0长期核心 | 一城起步，最多三城／一辖区／一都督／一野战军团 | 能验证长期城建、自动整军、三城协同及低频决策 |
| P0-R联动扩展 | 可选按键／专注、只读自选股故事 | 权限拒绝或断网不损核心玩法 |
| P1后续扩展 | 第二军团、更多地区与城市形态、人物及骑乘精修 | 核心成立后另立内容与性能验收 |

S1是开发切片，不宣传为完整60—90天游戏。P0以累计60—90个正常成长日作为首轮内容与平衡观察窗口，不代表已设计出90天全部美术和剧情，不承诺第90天必须完成。

## 3.2 核心容量

每城16个功能地块、10类建筑；一城有四个展示街区：安居、田仓、市集工造、城门营地。展示街区不是四套额外资源系统。主城最多2个普通建设项目并行，1个代表性工程另占工程位；二者都占用真实劳力和资源。

首批6名收藏武将、6件名器、4种坐骑保持不变。普通官吏和军官补足所有关键职位，不要求抽齐名将才自治。首个完整版本军团从0到1、编制从30到60再到90；这表示同一军团逐渐扩编，不宣称已经实现多军团大战。

多城是可选发展方向；始终只养一座主城也能完成核心收藏与城市成就。第二城不按日期强制赠送，也不是首城继续建设的门票。

# 04 轻量交互与注意力预算

## 4.1 玩家默认只负责三类决定

| 玩家负责 | 自动执行 |
| --- | --- |
| 城市方向与重要新区用途 | 项目排序、普通布局、生产、采购、运输、维护 |
| 关键太守／都督／统帅人选 | 普通岗位、代理接替、辖内授权任用、常规培养 |
| 重大扩张的目标与上限 | 已批准扩建、招募训练、整备与行动步骤 |

手动排产、逐件装备、逐人训练、逐车运输、每日收奖均不属于必做操作。高级面板保留查看和干预入口，但系统必须在玩家从不打开它们时正常发展。

## 4.2 提案上限不是任务配额

完成首次治理确认后，主动推入主公府的战略提案默认最短间隔72模拟小时，滚动168模拟小时最多2张；不是每城分别计数，不为凑数量制造问题。首屏只突出1张，全部未决议题列表最多保留3个独立主题；同主题更新，不复制卡片。

队列满时保留议题状态，不丢独特机会，不堵城市生产。其余主题由玩家主动打开发展规划时查询。玩家自行改方向、任免、看收藏不受提案冷却限制。安全越权直接阻止相关动作并合并说明，不借“紧急事件”绕过频率上限。

首次引导最多两个必需确认：接受长期治理与默认保护规则；选择或接受主城方向。起名、专精、装饰与联动都可跳过。普通官吏默认代理，招到名将后不强迫立即改任命。

## 4.3 不处理时的行为

不回复建议就沿用现行方针，不默认采用推荐选项。未授权的新城、新敌对对象、新军团等待；原城建设、生产、生活与已授权整备继续。没有“必须读完奏报才能继续生产”。

常规工程完成、任职成长、收藏获得直接入账。揭晓和庆祝可回看，关闭汇总不丢任何已得成果。不开启系统通知、不抢焦点、不弹Dock催办。

## 4.4 轻量体验验收目标

在无权限故障和无主动改策的标准场景中，首次确认后连续7成长日不需处理日常必答事件；城市仍可推进已有方向。短暂查看目标30—60秒理解主要变化，战略选择目标1—3分钟；这是可用性目标，不是要求玩家必须停留。

同一政策和相同授权时，每日看一次与每三日看一次的基础进度应一致，不以领奖或按键行为决定建设。错过新的可选战略选择可能改变发展路径，不宣称不同决策也必然同收益。

# 05 长周期与持续反馈

## 5.1 时间口径

正常情况下1现实小时映射1模拟小时；“成长日”是累计24小时正常模拟，不是登录天数。60—90日是设计观测范围，不是服务器赛季、倒计时、到点强制升级或锁定日期的关卡表。

教学加速和开发快进独立标记，不进入普通存档的时长统计。运行版本尚未完成本版调参，不得把旧版分钟级配方整体乘一个系数，就宣称已有90天内容。

## 5.2 成长节奏目标

| 时段参考 | 看得见的成果 | 应存在的取舍 |
| --- | --- | --- |
| 首次10分钟内 | 第一项修缮开工且跨过至少一个施工阶段 | 选择初期城市方向，不操作全部细节 |
| 第1—3成长日 | 基础住区改善、供应和街道开始成形 | 先安居还是先增加商品生产 |
| 第4—14成长日 | 一片街区有整体外观，民居与工作活动更丰富 | 自给、工造或贸易的侧重 |
| 第15—30成长日 | 明显的城市特色，营地开始正规化 | 民生、产业和已批准军务的资源倾斜 |
| 第31—60成长日 | 代表性工程、成熟产业、军团扩大；可选附属城 | 深耕主城还是扩展城市群 |
| 第61—90成长日 | 城区细节与长期网络进一步完善 | 维护现状、转型或选择下一项长期目标 |

阶段实际由人口、供给、工程和权限触发。材料与条件满足就能推进，不要求先等到某个日历日期。合理策略可以更快或更慢，所有时间均待平衡与真实体验验证。

## 5.3 不用漫长空等填充内容

首批修缮5—15分钟、早期普通工程0.5—3小时、中期建筑升级6—24小时、后期整片改造1—3日、代表性工程3—10日，均为起点配置。工程工时、材料与劳动供给共同约束推进，不能所有工程都只等一个计时器。

在可用资源和已授权方向存在时，目标每24—48成长小时至少出现一项有意义的城市变化；工程中的真实结构变化也计入，但眨眼、昼夜、计数增加和装饰粒子不计。长期无变化先报告阻塞原因和设计缺口，不能伪造进度或自动发资源掩盖问题。

大工程持续期间普通建设、经营和生活并行。无剩余合理投资时允许转入稳定经营；不为满足指标无限拆建或增加维护税。

# 06 城池结构、街区与布局

## 6.1 功能地块与可见街区

16地块承载实际建筑，街区将相邻功能组合为连续街巷。院墙、摊位、货场等附属表现从真实建筑与服务状态派生，不增加隐形产能、不另收每日维护操作。

地块有入口和道路节点。太守在可自治范围内安排布局，优先通达与既有用途；不移动玩家锁定建筑、收藏展示或命名。装饰与微调布局是可选表达，不提供足以迫使精算的巨大邻接收益。

主城先展示已开发区域，随着建设逐渐展宽镜头或解锁可见片区；不是一开局展示整座繁荣城，再只替换资源数字。缩略城景与完整城市视图使用同一建筑实例。

## 6.2 三类城市条件与可选分工

平川偏农桑与安居，青石偏矿产工造，临江偏商贸。所有城市仍有最低自给路径；优势通过生产、运输与布局机会表现，不让某城所有属性都最佳。城市名称可自定义。

农城可兼商贸，矿城可先自给；转型保留已建资产，并显示投入、在建工程与运输变化。不能一键改方向就瞬间换完整皮肤或重建全城。

## 6.3 新城的取得

新城可由开拓、合作恢复或已授权地区成果带来。主公决定是否取得以及边界，部属准备物资、安置和代理太守。建城材料分批运输至项目暂存库，齐备才开工；不复制开局国库、人物或军团。

贸易站、马场渠道与军事据点不等于完整城市；它们不自动增加一套人口、太守和待办。三城协同是系统验收场景，不是玩家必须完成的关卡。

# 07 建设项目与外观真实性

## 7.1 施工状态机

项目状态为拟议、待条件、已预留、施工中、暂停、完成、取消。每项工程关联建筑、地点、投入、劳力、工时、权限版本与唯一事务ID。开始前一次性预留本阶段材料；多阶段工程只对明示的下一阶段继续预留，不能先假开工后让库存为负。

| 实际完成比例 | 画面阶段 | 状态来源 |
| --- | --- | --- |
| 0%—15% | 清场、放线、材料堆放 | 已开工且有真实投入 |
| 15%—45% | 地基、立柱 | 累计有效施工工时 |
| 45%—80% | 梁架、屋顶逐步成形 | 同一项目的真实进展 |
| 80%—不足100% | 门窗、院落、收尾 | 有效工时，不提前启用产能 |
| 100%且完成事务提交 | 建筑正式营业或入住 | 只完成一次的结算事件 |

暂停保留当前阶段，停止实质施工动作并显示简短原因。人物可离场或整理工具，不能继续敲打并让进度前进。恢复沿原进度继续，不重新扣全部材料。

## 7.2 升级与真实收益

民居改善容量与生活展示；粮仓改变容量及堆放；集市增加服务与商铺形态；工坊改善处理能力和作业区；演武场支撑训练与营地。官署、驿站等无新增实际效果的升级不设置付费按钮。

建筑等级只在有明确收益时存在，基础上限三级；外观模块可以随人口、服务与使用状态逐步丰富，不把每一件晾衣架变成一级升级。施工模型和成熟模型共用占地、入口和深度关系。

## 7.3 劳力、并行与自动排程

居民劳力先满足基本供给，再在生产、普通工程和代表性工程之间分配。两普通建设位只代表最多可并行，不保证同时满速；大工程不能无代价使用另一份劳力。

太守根据缺口、已承诺事务、方针和净收益排序；供给不足时减缓非必要项目，不拆已建成果。避免反复切换：普通计划最低10模拟分钟再评估，重大安全变化与主公命令立即生效。

## 7.4 建筑与动画不能互相冒充

新增`BuildingInstance`为真实来源。旧版依据岗位容量画的工坊示意只作为历史开发演示，不映射为已建成建筑。动画只读取状态，不发材料、人口、经验或兵力；画面暂停、窗口隐藏不改变经济。

# 08 人口、繁荣与可见生活

## 8.1 三个成长维度

规模看真实人口与住房；生活看供给覆盖与服务可达；特色看持续产业结构和已经完成的街区。不得用一个“繁荣值”同时虚构三者，也不要求玩家每天填满若干进度条。

人口入住需要空余住房和持续基本供给，入住节奏配置化。满员后不自动挤出旧居民。短缺暂停增长、减缓非必要活动，不导致离线大批死亡或名将永久离开。

## 8.2 外观条件映射

| 城市对象 | 触发条件 | 可见变化 | 不得出现 |
| --- | --- | --- | --- |
| 住区 | 新住房完成且真实入住 | 院落用品、街巷居民逐步增加 | 空城却画成大量住户 |
| 粮仓 | 实物库存占容量的区间变化 | 空、少量、充裕三档堆放 | 预期到货被画成现存粮食 |
| 工坊 | 建成、已分配劳力、生产未受阻 | 工具、作业和成品活动 | 缺料仍假生产 |
| 商街 | 已完成商铺与实际履约 | 摊铺、客商、货物与出入 | 无合同却伪造贸易收入 |
| 营地 | 实际营建、编制、在营／在途状态 | 帐棚、营房、训练与出发 | 部队远征同时留一支实体分身 |

街景可用少量角色代表大量居民，但应标明表现抽象，不把动画人数直接当成人口计数。库存档位有迟滞区间，避免每次一袋粮进出导致整座粮仓反复换画面。

## 8.3 代表性工程

首批可选择商埠街区、工造院、田仓整治或营门整备之一为主要工程，其他方向仍可后续发展。工程分阶段有投入、作用与外观；不只在最后一天突然生成地标。

工程完成留下城市记忆并自动进入运营。没有“领奖后才开业”，不强迫开启下一篇章。P0不通过重复建同一地标无限叠收益。

# 09 太守、都督与长期治理

## 9.1 单城与多城的职责

单城任太守，负责本城建设、人口、生产、分工、地方贸易和城防。都督在至少两城的辖区中安排太守、城市分工、内部运输和所属军团发展；不是第一座城的高级工坊管理员。

军团指挥线与太守城务线并列归都督协调；未设都督时归主公的现行授权与中性协调器，不虚构隐形名将加成。城市越多也只提交一份势力汇总。

## 9.2 任命、方针、专项分开

官职长期有效，直到安全交接。施政方针持续有效，项目结束不续签。有明确结束条件的工程、建城或战役才是专项，可设总预算、范围、次数和退出条件。

下属可调用人才池与锁定条件明确；同一人只有一个主要实际职位。跨城调任有旅行与代理安排，到任才生效，不跨城瞬移，不重复获得两个岗位效果。

## 9.3 自主发展与保护线

部属可以建造授权类型、安排岗位、签正常合同、安排已经批准的兵员培养；不能新开敌对对象、增加城市或军团、处置唯一收藏、拆锁定区域、扩大专项额度。对军团规模可先一次批准目标编制，统帅分步达成。

人物能力和偏好影响合法方案的选择，不改变权限、制造资源或预读随机结果。普通官吏必须具备保供、代理和寻找替代路线的基本能力。

## 9.4 受阻后的自动处理

先查本城替代、辖内调拨、已授权采购、减缓非必要生产；不能解决才汇总结构性问题。没有可执行方案时保持安全维护，不高频生成相同请示。任免、开窗、读报告不刷新预算或生成经验。

# 10 财政、经济与持续再投资

## 10.1 一份国库与分城实物

六类常规资源为铜钱、粮食、木材、铁料、酒、器材。铜钱全势力唯一；实物在城市仓、项目预留、军需仓或运输中恰有一个位置。线索、能力与关系不是另一套通用付费货币。

基础采集和生产允许随时间创造价值。禁止的是无时间、无容量、无投入的即时重复套利，不是禁止正常加工收益。外部需求有限、报价锁定、已成交合同不追溯改价。

## 10.2 用户只选支出风格，系统算细账

首次治理提供稳健／均衡／积极再投资预设，默认均衡；对应再投资比例暂设25%／40%／60%。高级页可查看细账，不要求玩家手填每城预算。四模拟小时财政复核自动执行，不发到期提醒。

日常采购运输、建设再投资、战役／新城专项分别记账。额度是使用现有资产的权限，不是新钱。经营和专项已承诺的现金及实物不能再次分给建设。

设T为国库、R为已预留现金、F为保护金、O为必要运营尚未提交的保护额、S为上期外部经营回款减实际经营现金支出、K为有限资本结转，则新增资本授权为：

`B = max(0, min(政策资本上限, 再投资比例 × max(0,S) + K, T - R - F - O))`

S是净经营现金增量，不是会计利润；内部调拨、建城接收资产和测试赠予不计S。首次建设使用一次明确的开局发展额度，避免无建筑无收入、无收入无额度的死锁。过去已预留的资本只记R，不重复计K。

## 10.3 保护和恢复

粮食保护量以固定底线与未来基本居民需求的较大者计，军需单独预留。缺粮先停出口、酿酒等非必要消耗，再安排现有安全采购／自给。官署外采和基础农田不依赖消耗一种已经归零的启动货币。

不因城市变大收每日手动维护费。超出发展能力时减缓可选新投资，不能产生无法摆脱的负债或自动卖收藏。到达合理发展目标后允许积累与维护，不强迫把所有结余花光。

## 10.4 长期平衡方法

建筑、人口、劳力、需求、运力、军需和收藏共用预算，形成真实机会成本。长周期由产业升级、街区质量、承载能力与有限需求共同形成；禁止把所有建造统一拉长或所有成本统一指数放大。

旧`prototype-config.json`为分钟级v0.3历史夹具，不作为v0.4长期数值。新`city-growth-v0.4.json`先记录目标、边界和测试场景；各阶段价格与产能须完成模拟和试玩后才能宣称平衡。

# 11 军团随城市慢慢成长

## 11.1 四个可见阶段

| 阶段 | 实体状态 | 城中表现 | 玩家操作 |
| --- | --- | --- | --- |
| 地方守备 | 没有野战军团，城防状态独立 | 哨棚、巡逻、基础演武 | 可保持此状态不扩军 |
| 初建军团 | 已批准一军团，首队最多30兵 | 营房、征募与初级训练 | 一次确认目标和军需边界 |
| 扩成两队 | 总编制60，实际人员逐批培养 | 新训练区、物资与更多队列 | 上限已批则不重复审批 |
| 完整三队 | 总编制90，三队有不同兵种和训练 | 较完整营区与有序集结 | 维持、转型或给新的地区目标 |

编制上限、现役人数、伤兵、训练程度和在途状态分别记录。画面不可把空编制画成满员；实际人数不因升级立刻填满。P0单军团扩张是规模和质量成长，第二军团为P1，不在UI显示已可用。

## 11.2 批准目标，不逐批下命令

主公可选择“在民生稳定下逐步建成60人护送军团”。统帅和都督安排营建、器材、征募、训练与恢复。兵员来源采用有限本地训练名额，不复制伤兵，不因反复建营免费生成兵力。

军需不足时停止额外征募、非必要演练和新战斗；保留已有部队的休整，不因下班离线发生大批逃兵。上限达成后转入有限训练和维护，不自行组建第二军团。

## 11.3 轻量编队与装备

玩家选择守备／护送机动／有限攻坚的用途，统帅给出适配编队；手动配兵只是可选兴趣。普通器材按库存与政策自动配发，唯一名器和神驹仅在允许借用池中分配，不动玩家锁定收藏。

训练不要求点击启动每轮，无战斗也能练基础能力。属性成长不能替代地形、兵种与补给条件，兵器不会提高无关城务产能。

# 12 贸易、区域攻略与轻战争

## 12.1 商贸为城市打开机会

太守提交短缺／富余，都督按民生、已签合同、已批军务和发展方针协调。P0最多3运输队、4活动合同，最多2队外贸，民生紧急运输优先保留可用能力。单批容量100标准单位，五类实物各重1；大单必须拆运。

基本路线平川—青石20分钟、平川—临江15分钟，青石—临江经平川。运输去返和空车调位都有时间，在途只是预测供应，不是可立即消费的库存。到货和返队是不同事件。

## 12.2 战略目标而非关卡推土

主公批准通行权、合作渠道、指定据点或地区安全目标，都督比较交涉、护送、营救和清剿。战争结果落到商路、原料、马商或城市条件。未授权战争时，和平城建和全部核心收藏仍可行。

每战役保存对象、军团、总预算、最多行动数、累计损耗和撤退条件。默认最多4次军事行动；首次失败后只允许一次有实质变化且风险合格的替代军事尝试，不能靠重命名或换将重置。

## 12.3 自动战斗与损耗

沿用四兵种和三路线的小规模回合模型，最多12回合。枪阵优势须正面迎击、弓兵近身受压、盾兵护送、骑兵依合法侧路机动；不需要实时点技能。战报来自同一快照与种子，动画不重新结算。

失败消耗授权军需、产生伤兵并可能没有回报；武将、兵器和神驹不永久丢失。伤兵自动恢复，治疗支出属于既定预算。核心默认无离线袭城，不能通过增加突发守城把玩家拉回电脑。

# 13 人物属性与自动培养

## 13.1 五维基础与四类职业经验

统一采用统率、武勇、智谋、内政、魅力五维基础属性；职业经验分治理、统筹、军务、交涉。废止将v0.3四种能力同时当作另一套基础属性的口径。当前代码已存在五维与职业经验结构，本版不声称全部属性效果已实现。

统率服务军队组织，武勇服务个人突击护卫，智谋服务合法情报内的判断，内政服务供需与建设，魅力服务招贤合作。职业成长提高岗位适配与少量特色做法，不把基本保供和撤退能力锁在等级后。

## 13.2 培养由职责自然发生

有效在岗治理、持续供给、真实合同与已完成行动积累对应经验；稳定维护同样可成长，不鼓励先制造缺粮再修复刷经验。同一人物的经验不按管理城市数简单倍增，事件ID和任职时段防止重复计入。

低优先级人才可自动研习，默认不占主公待办。设定培养方向后长期有效，升级自动应用安全默认分支，可在人才页查看；关键跨职提拔属于人事决策，不是每天加点。普通官吏不会故意犯错来突出名将。

## 13.3 人物为城市服务

荀彧偏供给，鲁肃偏合作，诸葛亮偏工造瓶颈；赵云、关羽、张飞保留各自军事和生活特色，均是游戏设定。能力与偏好只改变合法方案，不突破预算、锁人和战争边界。

履历以“改善了哪座城、解决了什么瓶颈”展示，不把全城收入全部归功一个人。培养树精修优先级低于真实城建，不能再让人物面板成为默认主界面。

# 14 收藏融入城市，而非另一套打卡

## 14.1 三条路径

武将通过结识与共同经历常驻邀请；名器通过线索、取得残件与修复；神驹通过马商渠道、寻访和驯养。6将、6器、4马均至少有一条一城、非战争、非联网可达路径，不能互相循环依赖。

主心愿最多1个，关注目标3个。玩家选定路径和最大投入后，普通步骤自动推进、物品自动入账。没有未读就停工、每日赠礼或重复碎片升星；不选新心愿也不停止城市发展。

## 14.2 藏品有城中位置

官署藏架展示名器，马厩展示坐骑，人物在真实居城与岗位出现；随收藏丰富有环境变化。已借出的物品显示铭牌，不复制实物。未实现骑乘时准确标记，不用给人物贴马图冒充骨架完成。

每人最多1件兵器、1匹坐骑。锁定收藏不被自动重配；出征途中不更换快照装备。唯一收藏不销毁、不自动出售、不作为升级材料。重复命中按可见规则换相关线索或普通材料。

## 14.3 取得经历自动保留

记录来源城市、参与人物、主公决定和完成项目。无须当时在线看揭晓，不为看动画再次发资源。成就记录成长而非限制发展，不强制凑固定三人组合才能治理。

# 15 城市成长册与长期归属

## 15.1 同视角回顾

自动在建城起点、重要街区／军团阶段、代表性工程完工及正常成长7／30／60／90日保存游戏内快照。日期节点只用于记录，不发经济奖、不强迫阶段结算。没到对应天数也可主动拍一张城景。

快照保存建筑、人口、装饰和代表性活动的可序列化状态及版本。图像由游戏自身渲染，不截桌面、不录屏、不读取工作窗口。离线经过多个节点时按当时实际状态记录，不拿最后一张城景冒充全部历史。

## 15.2 纪念与存储

默认最多60个自动里程碑，重要节点优先，其余按时间合并；最多20个用户固定快照独立保留，超限先询问替换或导出。历史状态不随新皮肤被静默改写，旧资源缺失时显示兼容占位与版本提示。

对比模式保持相同城池、镜头与昼夜，能指出新增建筑、改善街区和营地变化；隐藏数字后仍应可辨成长。不同方针应出现结构差异，而非相同城换色。

## 15.3 没有强制终点

一座城可以继续深耕、建设附城，也可以维持现状。篇章名称只用于回顾，不需要手动开启才自治。不在30或90日清档、不补发未登录罚单、不把旧收藏降为无用物。后续内容有限时明确说明，不宣传无限模拟人生。

# 16 时间、离线与安全休整

## 16.1 延长离线容忍，保留有限计算边界

本版目标把正常离线补算上限由7日延长至30现实日；这是一项待实现的规则迁移，现有core-0.1仍为7日。上限必须由存档版本与界面真实显示，不能文档改了就宣称客户端已延长。

日常治理离线默认按一次接受的长期权限续行，包括普通建设、岗位、贸易、合规人事与已批准的非战斗整军。主动开战的离线续行单独控制，默认只完成已启动军事行动；开启后仍受专项预算、次数和对象边界限制。

## 16.2 因果时间与现实水位分开

正常区间统一推进生产、项目、人口、经验、物流、预算与成长册；不使用最终产速乘整段时间。达到30日上限后进入安全休整，停止新增循环和不利消耗，不累计新的日常额度或无限任务链。

此前已完全承诺资源的有限行动，可在剩余真实离线时长内安全排空；部分备料未开工工程不能借排空偷偷开始。保存现实时间水位和游戏因果时间，重启、时区改变和反复打开不重复补算。

## 16.3 长时间离开以后

回来只显示一份城市变化汇总与最多1项突出决策，原官职和方针自动恢复未来治理。未处理战略分支继续等待，正常生产不要求逐城恢复。超上限没有倒扣、城市被抢或藏品丢失。

时钟后退按零新增间隔处理；异常前跳按上限并提示，不封号、不强制联网校时。30日与90日性能是独立测试，优化不能省略中途缺料、项目完工和角色到任。

# 17 Mac界面与日常观看

## 17.1 默认先看城

默认入口改为关注主城的城景，不再首先打开人物表或待批列表。桌角约640×240 pt，完整城景和管理窗可主动展开；这些是布局参考，不锁死用户缩放。

顶部最多3条成果摘要，1张主要决策可折叠。主要导航为城景、发展方向、城市成长册；人物、预算、军团细账、物流放在详情层。营地可直接点开军团成长，不要求学习复杂菜单。

## 17.2 生命周期与可访问性

保持菜单栏和Dock恢复入口。关管理窗仅关窗，关城景收起，Command-Q退出并停止自有采集与网络。不得伪装系统进程，不保证屏幕共享隐身，不自动覆盖全屏应用。

不抢焦点、默认静音、无系统通知。支持键盘导航、VoiceOver文本等价、字体缩放、减少动态效果和1×／2×显示；隐藏停止渲染，显示帧率不改变进度。

## 17.3 展示诚实

城景从真实`CityAppearanceSnapshot`读取；样板和演示独立标签，不写存档、不授予武将或建筑。供给短缺、军团在外、工地暂停要有等价文字说明，不只靠颜色。重要相机变化需玩家主动，不突然打断工作。

# 18 现实联动、隐私与外部资料

## 18.1 联动是可关闭的陪伴层

按键或主动专注提供有限项目助力：每日最多60分钟、最多积存180分钟、每项目不超过基础工时20%。不影响战斗伤害、普通资源产速或行军，不影响人物经验；不把按键数叫作字数或工作效率。

自选最多50条、3家绑定商号，只读名单和报价，改变已有来访的故事呈现；无每日三张新增任务。行情涨跌不改变游戏经济、军事胜负或收藏稀有率，拒绝接入仍有同等基础事件。

## 18.2 最小权限

输入计数默认关闭、应用白名单默认空，用户主动允许后才处理聚合次数。原始键标识只在内存去重，不保存顺序、文字、标题、聊天、截图或剪贴板。不能保证识别所有密码框，应明确限制与暂停入口，不绕过安全输入和企业策略。

退出、锁屏、睡眠、权限撤回或事件源失败停止新计数。行情凭证不进入Git、日志或存档；不读持仓、不含下单、不要求入金换奖励。外部数据不可用就降级中性故事，不阻塞保存。

## 18.3 平台资料边界

macOS／Apple Silicon原生继续为主线，输入监控、签名、公证与实际数据授权沿用独立发布审查。技术引用保留在历史架构与原PRD中，本版没有据此声称已取得新权限、支持用户具体系统或完成M4能耗测试。

# 19 架构契约与当前代码差距

## 19.1 仍采用展示与模拟分离

纯Swift模拟核心唯一写入状态；SwiftUI／AppKit负责窗口和操作，SpriteKit负责城景。太守、都督、玩家和扩展都通过同一命令入口，校验权限、版本、资源与预算后原子提交。

现实数据、动画帧和预览样板不能直接改城市。代码先建立可靠的项目事件，再让画面订阅；禁止用动画播放结束回调作为发资源的唯一入口。

## 19.2 必需新增实体

| 实体 | 关键字段与不变量 |
| --- | --- |
| BuildingInstance | 城市、地块、类型、等级、运营状态；一实体不同时建成和施工 |
| ConstructionProject | 阶段、真实投入、工时、劳力、预留、权限版本；完成只入账一次 |
| NeighborhoodState | 组成建筑、服务与外观里程碑；视觉繁荣有证据 |
| CityAppearanceSnapshot | 城景版本、可见建筑与活动；只读、可复现 |
| DevelopmentPlan | 持续方向、允许区块、资本规则、当前瓶颈；不短期续任 |
| LegionGrowthPlan | 批准编制、实际兵力、训练与补给；不自动扩第二军团 |
| CityMemory | 因果时间、快照版本、决定／结果引用；无桌面截图 |
| DecisionBudget | 全势力滚动窗口、合并主题、当前卡；不按城市倍增 |

## 19.3 存档与性能

资源采用整数或定点口径，随机与规则版本化；命令ID去重、revision校验、单写入者。至少每60秒保存，关键预留、完成、任免立即持久化；失败不公布半份结果。保留3份有效备份，损坏不静默重建覆盖。

每次仅渲染关注城市，其他城市保留模拟；可见30fps、低能耗15fps为上限目标，不锁高刷。30日补算目标P95不超过10秒，完整90日无界面仿真目标不超过60秒，均须实际测量，不能由Swift编译通过推断。

隐藏停止城景动画和无意义网络轮询，不阻止睡眠。用户M4机型、内存、系统与屏幕配置需要在验收报告记录；不能把GitHub arm64运行器等同用户实机。

## 19.4 已实现与待实现

仓库visual-0.2已有基础生产、太守调岗、五维与职业经验、存档、2D人物和街景表现；BUILD_STATUS记录了原70项测试与Mac构建。这是历史实现证据，不是本版玩法验收。

真实建筑实例、持续建设、街区成长、军团养成、30日补算、成长册和新决策预算均仍待实现。本轮只交付规格，不改Sources、游戏规则版本或运行存档schema。

# 20 开发优先级与交付门槛

| 顺序 | 工作包 | 出关条件 |
| --- | --- | --- |
| G1 城建数据 | 建筑实例、项目工时、预留、取消／恢复、保存 | 同一工地可恢复，无资源重复消费 |
| G2 可见施工 | 五阶段外观、入口道路、角色与状态一致 | 主城从空地到营业可逐步观察 |
| G3 太守连续发展 | 方向驱动连续建设、劳力、保护线、再投资 | 无逐项确认可完成三个合理项目 |
| G4 街区与轻交互 | 人口／服务外观、成果汇总、低频决策、成长册 | 同视角能辨成长，不产生日常待办 |
| G5 军团慢扩 | 营建、30／60／90编制、自动征募训练、有限军需 | 一次目标授权自动推进且不掏空民生 |
| G6 多城与长期调参 | 太守任用、物流、财政、30／60／90日仿真 | 一城成立、三城不增加必做杂务 |
| G7 内容与发行 | 收藏、来源检查、M4 GUI／能耗／签名 | 核心体验与稳定性通过，不以文档充成品 |
| G8 可选联动 | 计数、专注、行情只读适配 | 独立验收，不阻塞核心版本 |

G1—G4优先于完整培养树、马匹复杂动作、全国战争和行情。可以保留既有人物动画，但不能继续靠增加动作数量代替城市真实变化。初期用可替换的原创模块化美术，不先制作几十个名将。

# 21 玩法验收、仿真与证据

## 21.1 三种测试不可混算

静态规格检查验证编号、字段、阶段边界、容量和版本；运行测试验证经济、项目、权限与离线一致性；用户体验测试验证看得见和玩得轻。三者分别报告，检查JSON通过不等于30日模拟通过。

使用v0.4独立CG编号验收，旧AC001—AC100保留历史引用但不自动继承通过。现有70项源码测试没有因为PRD更新而增加，也不代表本版已实现。

## 21.2 30／60／90日测试矩阵

供给、贸易、工造、备军和均衡五种方针，每种分别运行每日一次、每三日一次、每周一次的查看策略；保持相同权限、决策和随机种子，不启用按键或行情奖励。90日用不超过30日的连续补算窗口推进，另测一次超过30日的休整，不混淆两种情况。

至少包含断路、材料耗尽、无名将、拒绝扩城、没有战争、改变方针、锁定街区、长离线和存档写失败。记录物资／现金守恒、有效工程数、停滞时长、未决卡数、军团损耗、玩家必需操作数和可见城市里程碑。

无可见变化但仍有合法可负担项目持续48成长小时，是需要定位的节奏缺陷；不把稳定终局、玩家主动暂停或未授权新方向误算成缺陷。每日和三日查看的同策略资源应等价，不能以模拟误差掩盖领奖依赖。

## 21.3 同视角视觉检查

开局、7／30／60／90成长日与各代表工程里程碑，分别导出游戏内同角度城景。隐藏数字后，测试者应能区分早中后期、指出至少两种真实结构变化。不同方针的城景应体现建筑、街区或营地差异，不只换色。

长周期是否舒服仍需实际低频使用测试；加速仿真不能证明90天留存或代替手感。所有未来统计写“目标／待测”，禁止无证据宣称平衡或不耗电。

# 22 版本迁移与变更纪律

## 22.1 明确废止的旧口径

废止以人物与议事为首屏、每4小时最多一张常规提案／每天最多6张的旧节奏；改为城景优先、全势力每72小时至多一张、滚动7日最多两张的低频提案。它们是上限，不强制生成。

废止将10分钟建造简单放大为长周期的方法。旧三级建筑与三城容量可沿用，但新增街区形态、过程真实性与成长册验收。旧七天离线改为三十天设计目标，实际源码迁移完成前仍如实显示旧上限。

人才统一五维加职业经验，人物养成为城市服务；完整培养分支不再阻塞城建。军团在同一编制目标内自动发展，不逐批批准，但不得增加未授权军团或战争对象。

## 22.2 仓库文件与历史证据

`docs/PRD.md`为本版权威产品稿；`spec/city-growth-v0.4.json`为目标与约束，不由旧游戏自动加载。`docs/ACCEPTANCE.md`与`spec/acceptance-v0.4.json`使用相同CG用例；`scripts/validate_spec_v04.py`只做静态规格检查。

旧PRD、旧100用例和manifest保留历史身份；旧静态脚本在Git历史保留，当前入口转调v0.4检查器，不把它们的旧哈希宣称为当前交付哈希。更新README、实施计划与架构影响说明，避免程序员同时执行两个相互矛盾的目标。

后续真正改变运行规则时，单独提高rule_version、备份旧存档、提供确定迁移与回滚说明。不得仅替换文案便静默改变已经在途的战斗、已预留成本或过去经验。

以下均是状态触发的可选战略分支，不按日期强制弹出。同一主题只有一个当前议题，每项默认继续原方针；已授权的细节无需再次询问。
